## 2. 주요 개정

- FE의 별도 investigation/run 경로를 02의 analyses/reports/jobs로 통일했다. job_id=analysis_id/report_id이며 통합 작업 목록과 일정 발생 이력을 추가했다.
- CPC별 Namespace·역할 권한을 함께 다루고 결과·지식·근거·모델 입력에서도 범위를 유지한다.
- job.status, result_status, topics/assessments.status, quality 객체, narrative_status를 분리했다.
- retry 명령의 멱등 기록·과거 attempt·공유 토큰 예약·설정 스냅샷과 일정 revision 효력 구간을 구체화했다.
- Pod 조사, KB 발행, 모델/라우팅, 일·주·월 일정, HTML·CSV, 전체 O/R 주제의 화면 진입을 연결했다.
- 할당 이력은 Mimir 원본 시각·관계 이력에서 공통 도구가 복원한다. 장시간 저활동은 동일 전용 할당 관계의 60분 창으로 판정하고 차트 간격과 계산 해상도를 분리했다.

## 3. 기준과 검증 상태

이 묶음의 01~08은 개발 기준이다. API 경로·상태·테이블·후보 적격성처럼 이번에 구체화한 내용도 포함하며 현재 운영 API가 이미 그렇다는 뜻은 아니다. 실제 수집 기록은 sources의 대상·시각·버전에 한정한다. 문서 개정이 실제 검수 PASS를 의미하지 않는다.

계산의 기존 5%·60분·95%·90% 값은 유지한다. 짧은 할당·후보 단위·창 정렬·검사 유효성을 보완했으므로 새 실행의 criteria와 결과 스키마는 1.1로 고정한다. 과거 v1.0 결과는 원래 기준을 보존한다.

**두 CPC의 중앙 조회·매핑 활용 기반은 유지한다.** CPC-2 직접 수집·UID 조인·GPU_UTIL의 짧은 검증 구간과 CPC-1 직접 경로 전환·장기 이력·최종 재배포 후 Loki 수신은 서로 다른 검증 항목이다. C04에 대상별 모의 검수·실환경 산출·부족 처리·실제 필수 인수 상태를 분리해 기록한다.

Endpoint·권한 연계·원본 갱신 주기·예산·episode·성능 목표·RPO/RTO 등 C01~C12의 실제 값은 담당자가 해당 시험 전에 채운다. 임의 수치로 채우거나 미입력을 완료로 바꾸지 않았다. T01~T40의 실제 서비스 시험은 NOT RUN 상태다.

## 4. 출처 묶음

[출처 안내](<sources/출처_안내.md>)와 [원문 목록과 SHA-256](<sources/원문_목록과_지문.json>)에 외부 검토서, 기존 개발 산출물, GUI/FE, 최신 역할·공통판단·Backend·KB·수집 기록을 포함했다. 외부 검토서에서 ‘자료를 찾지 못함’으로 남긴 최신 근거는 이 작업 폴더에서 찾아 대조했다. 파일 지문은 이번에 읽고 보존한 버전을 식별한다.

sources는 과거 원문의 경로를 조정한 저장소 열람본이며, 변경 전 원문은 묶음 안내의 ZIP에 보존했다. 내부의 예전 파일 경로·제안·미완료 표시는 작성 당시 맥락이며 현재 구현 계약을 대신하지 않는다. 상세 출처 비교는 09를 따른다.
