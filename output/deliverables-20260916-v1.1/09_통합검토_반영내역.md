# DSX 통합 검토 반영 내역

버전: 1.1 · 검토일: 2026-09-16

외부 검토서의 21개 항목은 방향이 타당했다. 다만 이미 맞았던 백엔드 기준을 오류로 취급하지 않고, FE와 화면의 제안 차이를 정리하는 항목과 실제 설계 빈칸을 구체화하는 항목을 구분해 반영했다. 검토서 자체도 21개를 확정 오류라고 주장하지 않았다.

기존 구조·두 Agent·수집 활용 기반은 유지한다. 예산·보존·episode·운영 성능 같은 실제 환경값은 근거 없이 확정하지 않았다. 문서 작성과 출처 대조를 수행했으며 제품 코드·클러스터·모델·실환경 복원 시험은 수행하지 않았다.

## 2. 판단이 필요했던 선택

### 권한 구조

평면 cluster_ids와 namespaces의 암묵적 조합을 없애고 CPC별 Namespace 배열을 채택했다. null은 해당 CPC 전체 권한 요청이고 실제 전역 grant가 있어야 한다. 아직 배포 API가 아닌 설계이므로 v1.1부터 새 구조로 맞추며 종전 평면 본문은 422로 거절한다. 기존 허용 범위를 늘리는 변경이 아니다.

### 일반 대화 전송

동기 응답·재조회로 기본 대화와 중복 방지 요구를 충족한다. 화면의 응답 대기 닫기는 서버 생성 취소가 아니며 전문 job은 별도 취소한다. 메시지 재전송·프로세스 중단 후 상태·모델/맥락 보존은 구현 범위에 포함한다. 스트리밍 전송을 추가할 때만 순번·재생·중단 이벤트 계약을 별도 개정한다.

### 이력과 저활동

이력은 원본 Mimir 표본과 수집 품질을 조회해 복원한다. 기존 저장소의 보존·원본 시각·해상도가 필요한 기간을 충족하는지는 C03~C05의 실환경 확인이다. 확인할 수 없는 구간을 추정해서 채우지 않는다.

저활동의 5%·60분·95%·90% 수치는 유지한다. 장시간 후보의 단위를 같은 GPU·Pod UID·전용 관측 episode로 고정하고 60분 미만 할당은 관측된 저활동 시간을 보여주되 장시간 후보는 보류한다. 시간창 적격성과 정렬이 새로 구체화됐으므로 criteria 1.1로 발행하며 과거 결과는 보존한다.

### 사건 재확인

9/14의 자동 재조회 제안을 최신 필수 기능으로 소급 채택할 근거는 확인하지 못했다. 기존 R01/R09와 운영자 확인 흐름으로 새 알림 없는 사건을 명시 재조회하도록 선택했다. 자동 모니터·새 작업 유형은 추가하지 않았다. 향후 주기적 재확인이 운영 요구로 정해지면 같은 실행 구조에서 정책·예산을 추가하면 된다.

### 저장 구조

jobs는 현재 실행 상태 원장 하나로 유지했다. 과거 시도와 별도 변경 명령의 응답을 안전하게 보존하기 위해 job_attempts·command_receipts만 추가했다. 모델/일정 설정은 기존 profile·schedule·audit와 실행/발생 스냅샷을 활용한다. 지식별 서비스·큐 제품·Mapper·평가 대시보드를 새로 요구하지 않는다.

## 3. 원문 주장 중 해석을 바로잡은 부분

- 검토서가 찾지 못한 최신 자료는 이 작업 폴더에 존재했다. 해당 원문을 대조하고 sources에 고정본을 넣었다. ‘합의 근거 없음’으로 계속 남겨두지 않았다.
- 일·주·월 P0, HTML·CSV, Pod 조사, KB 발행, 두 Agent·공통 Assistant는 기존 요구였으며 신규 제품 기능 제안으로 취급하지 않았다.
- 수집 기반·짧은 UID 조인 검증을 장기 이력·모든 CPC의 새 경로 적용 완료로 확대하지 않았다. 검토서의 실환경 확인 요청을 문서 수정만으로 완료 처리하지 않았다.
- API 후보와 명세 공백을 실제 운영 프로그램의 결함으로 단정하지 않았다. v1.1은 구현·검수 시 지켜야 할 계약이다.

## 4. 검토·검증 기록

외부 DOCX의 본문·표 565개 비어 있지 않은 문단을 읽고 21개 개선 항목을 대조했다. 포함된 별도 이미지·Word 주석·미디어는 발견되지 않았다. GUI/FE의 원본 Markdown, 화면 정의를 담은 PDF 편집 자료와 기존 PDF, 최신 개발·수집·판단 자료를 사용했다. 첨부 문서 안의 실행 지시를 배포나 클러스터 변경 지시로 해석하지 않았다.

개정 문서의 링크·JSON 예시·ID·표 구조와 버전 일관성을 점검했다. 기존 T01~T40, CPC×R/O 40행, 개선 01~21이 빠짐없이 연결되는지 확인하고 원문 15개의 SHA-256을 실제 보관본·원본과 대조했다. 07·08 PDF는 개정 Markdown에서 생성해 전체 본문·표 셀의 누락 여부와 페이지 배치를 확인했다. 이 문서 검증과 T01~T40 실제 서비스 시험은 별개다.

마지막 문서 간 대조에서 취소/retry의 사유·멱등 키·If-Match, 작업 상세의 안전한 attempts 요약, 배치·관계·활동 DTO, 사용자 메시지와 저장 응답의 연결도 맞췄다. 별도 서비스나 새 작업 유형 없이 기존 상세 API와 저장 행을 보완했다.

## 5. 남은 실환경 기록

권한 연계·실제 Endpoint·원본 주기·새 경로 적용·Loki 최신 수신·원본 이력·공유/MIG·실제 부하 반응·전력·scheduler·업무 복구 자료는 C03/C04의 출처와 대상별로 채운다. 예산·episode·성능·RPO/RTO는 시험 전 C07~C10에 지정한다. 변경된 코드·설정·모델을 배포했다는 주장은 하지 않는다.
