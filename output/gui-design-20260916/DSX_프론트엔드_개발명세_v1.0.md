## 01. 목적과 적용 범위

이 문서는 프론트엔드 개발의 화면·동작·데이터 경계를 정한다. 웹 시안은 메뉴와 배치를 검토하기 위한 정적 프로토타입이다. 실제 운영 데이터를 조회하거나 LLM을 호출하지 않는다. 가상 장비·값·사건을 실제 검증 결과로 해석하지 않는다.

대시보드에서 시스템을 파악하고 필요할 때 Assistant를 연다. 일반 질문·개념 설명·가벼운 조회는 공통 Assistant가 처리한다. 긴 장애 조사와 보고서 작성은 두 전문 Agent의 비동기 작업으로 연결한다. 일반 질의를 위해 세 번째 전문 Agent를 추가하지 않는다.

| 구분 | 이번 산출물 / 개발 범위 |
|---|---|
| 웹 구현 | 7개 메뉴, 화면 이동, 공통 채팅 예시, 작업 연결, 조사·보고서 접수 및 작업 단계 시뮬레이션, 사내 모델 설정 |
| PDF 화면설계 | 웹 화면 캡처, 화면 번호, 영역별 의도, 연결 동작, 보류 조건 |
| 개발 명세 | 화면별 계약, 공통 컴포넌트, API 제안, 상태·권한·오류·반응형·인수 기준 |
| 후속 실제 개발 | 인증, 서버 조회, 영속 작업, 실제 추론, 실시간 갱신, 보고서 파일 생성, 정기 스케줄 저장 |
| 범위 제외 | GPU reset / drain / reboot / 자원 회수 자동 실행, 외부 상용 모델 연결, 전체 수집 시스템 재구성 |

상태 정의와 판단 기준은 최신 Agent 설계를 따른다. 아래 API 경로·필드·폴링 간격·권한 역할·화면 라우트는 프론트엔드 구현을 위한 제안이며, 기존 서버의 확정 계약이 아니다. 구현 전에 백엔드 담당자와 합의한다.

## 02. 최신 설계 반영 사항

| 기존 화면의 오해 가능성 | DESIGN 05 기준 |
|---|---|
| 모든 질문은 둘 중 한 Agent 선택 | 공통 Assistant를 기본 진입으로 사용. 전문 분석이 필요한 경우에만 연결 |
| 분석 요청 즉시 결과 화면 표시 | 요청 접수 → 작업 이력 → 실행·저장 완료 → 결과 열기 |
| 완료 = 신뢰할 수 있는 결과 | 실행 상태와 결과 품질을 별도 표시. succeeded + partial / blocked 허용 |
| 현재 GPU↔Pod 연결 미완료 | 현재 UUID 매핑과 KSM Pod UID 연결은 확인. 과거 할당 구간은 별도 검증 |
| Pending은 미배치 상태 | 배치 / GPU 매핑 / GPU 활동의 세 축을 독립적으로 표시 |
| 중앙 조회 가능 = 모든 기간 데이터 충분 | 최신 수신·필드·기간·관계·적용 조건별 준비 상태 표시 |
| 백엔드 8개 기능 = 8개 메뉴·서비스 | 사용자 업무 기준 7개 메뉴. API와 두 Worker, 공통 기능은 화면에서 내부 구현으로 취급 |

수집 관련 근거는 2026-09-15 진행 자료와 최신 Agent 문서다. CPC-2는 KSM·DCGM Exporter를 Alloy가 EndpointSlice로 직접 수집하고 관측 Gateway를 통해 Mimir에 전달하는 경로가 확인됐다. CPC-1의 같은 경로 전환까지 확인한 것은 아니다. GPU Ops용 Prometheus 중계 제거와 기존 Prometheus / Run:ai 소비자 유지도 구분한다.

KSM 1개 + Exporter 2개는 scrape target 수다. GPU 수가 아니다. 15초 수집 주기는 원천 센서의 갱신 주기를 보장하지 않는다. 짧은 검증 구간으로 주간 이력을 확보했다고 표시하지 않는다. Loki는 재배포 이후 최신 수신을 재확인해야 한다.

## 04. 공통 레이아웃과 탐색

| 영역 | 구성 | 동작 계약 |
|---|---|---|
| 좌측 메뉴 | 브랜드, 7개 메뉴, 사용자 표시 | 현재 메뉴 강조, 하위 화면에서도 상위 메뉴 유지 |
| 상단 | 화면 경로, 관제 범위, AI에게 질문 | 전역 관제 범위는 목록·관측 조회에 적용. 저장 결과의 범위를 덮어쓰지 않음 |
| 본문 | 제목, 범위·시각, 주요 행동, 내용 | 첫 화면에서 대상과 할 일을 확인. 긴 본문은 자연스럽게 스크롤 |
| 우측 Assistant | 대화 범위, 메시지, 바로가기, 입력 | 필요할 때 열고 닫기. 현재 화면과 함께 보기 / 대화 펼치기 |
| 결과 근거 | 로그, 지표, 문서 버전, 한계 | 원인 후보의 지지·반박·미확인 근거에서 해당 자료로 이동 |
| 상태 알림 | 접수 성공, 저장 실패, 관측 지연 | 즉시 동작 결과는 role=status, 입력 오류는 role=alert |

화면 이동으로 대화 초안을 지우지 않는다. 사건·보고서·작업의 저장 범위는 고정한다. 전역 범위를 바꿔도 기존 메시지와 결과는 유지하고, “현재 화면 범위 적용”을 눌렀을 때 이후 질문의 범위만 바꾼다.

실제 구현에서는 조회 가능한 범위·기간을 URL에 저장한다. 비밀 키·원문 로그·긴 질문을 URL에 넣지 않는다. 새로고침·뒤로 가기·직접 링크 진입을 지원한다. 잘못된 리소스는 빈 결과와 구분해 “없거나 접근할 수 없는 항목”으로 안내한다.

## 05. S01 운영 대시보드

목적: 전체 시스템의 우선 검토 대상을 정하고, 관측·조사·분석으로 이동한다.

| 영역 | 표시 / 입력 | 상호작용·목적지 |
|---|---|---|
| 범위·기간 | cluster 범위, 최근 1시간 / 24시간 / 7일, 기준 시각 | 변경 시 조회 키 갱신. 사용자 지정 기간은 실제 구현에서 추가 |
| 요약 카드 | 열린 사건, 관측 지연, GPU 메모리, 분석 준비 | 사건→S05, 지연·준비→S04, GPU→S02 |
| 먼저 확인할 항목 | 대상, 이유, 근거 품질, 다음 행동 | 사건 결과 S07 / 관측 품질 S04 |
| 대상 선택 | Node 타일, 모델, GPU 수, 관측·장비 상태 | 복수 선택과 전체 범위. 선택 대상은 칩으로 명시 |
| 자원 추이 | VRAM / 활동 / 전력, 단위, 시각, 누락 | 이 그래프에 질문 → 선택 대상·기간·지표가 포함된 S16 |
| 최근 사건 | 사건 ID, 대상, 발생 시각, 처리 상태 | 개별 사건 조사 또는 질문 |

수치가 없는 항목은 0 대신 “근거 부족”과 필요한 입력을 표시한다. 오래된 마지막 값을 현재 값처럼 연결해 그리지 않는다. 표본이 일부라도 표시할 때는 실제 관측 구간·대상 수와 제외 범위를 함께 전달한다. 그래프 축·단위와 집계 기준을 생략하지 않는다.

API 제안: GET /api/v1/overview, GET /api/v1/metrics/series. 응답은 observed_at / coverage / quality / missing_inputs를 포함한다. 브라우저가 임의 임계값으로 장애·저활동을 확정하지 않는다.

인수 기준: 지연 Node만 선택했을 때 현재 추이 판단을 보류한다. 일반 질문도 가능하며, 전체 시스템 질문과 선택 대상 질문의 범위가 눈에 보인다.

## 06. S02-S04 자산·관측

S02는 Node → GPU 상세를 선택한다. S03은 Pod와 실제 GPU의 관계를 확인한다. S04는 입력별로 어떤 분석이 가능한지 설명한다.

| 화면 | 핵심 표시 | 동작 / 예외 |
|---|---|---|
| S02 | cluster / Node / GPU UUID, 모델, 마지막 관측, 지표·단위 | 선택 GPU 질문, 조사 시작. Node 변경 시 GPU 선택을 유효 범위로 초기화 |
| S03 | Pod UID, namespace, 배치, GPU 매핑, 활동, 관계 유효 시각 | 현재 / 사건 시각 전환. 과거가 없으면 현재 매핑으로 채우지 않음 |
| S04 | 소스별 수신, 지연·누락, 기간·항목별 품질, 필요한 입력 | 대상 상세 및 S15 데이터 연결로 이동 |

| 독립 축 | API enum | 화면 해석 |
|---|---|---|
| placement | unbound / bound / unknown | Pod 배치. Kubernetes phase와 동일하지 않음 |
| mapping | matched / ambiguous / not_observed / unknown | GPU 관계. matched도 공유일 수 있음 |
| activity | active_observed / low_activity_candidate / insufficient_data / not_applicable | 실제 유효 활동 근거와 적용 가능성 |

관계의 기준 키는 cluster+GPU UUID, cluster+Pod UID다. 이름은 표시용이며 동일 이름 재생성을 구분한다. Node는 UID를 우선하고, 없는 경우 백엔드가 제한된 대체 키의 품질을 알려야 한다. zone / node_group은 선택 가능한 차원이지 필수 소유·계층 구조가 아니다.

공유 GPU에는 여러 Pod가 매핑될 수 있다. 장치 활동을 각 Pod의 활동으로 복제하지 않는다. 물리 GPU / MIG / 공유 단위는 구분하고 숫자를 단순 합산하지 않는다. 매핑 미관측은 해제나 미할당 확정이 아니다. 활동률 0인 현재 매핑을 필터로 제거하지 않는다.

API 제안: GET /assets, /assets/{id}/gpus, /mappings?at=..., /observability/quality. 실제 구현에는 검색·상태 필터·페이지네이션을 추가한다. 시안은 8개 가상 Node를 타일로 표현한다.

## 07. S05-S07B RCA 조사

| 화면 | 입력 / 내용 | 주요 행동 |
|---|---|---|
| S05 조사 목록 | 사건 ID 또는 직접 요청, 대상, 상태, 최근 실행 | 새 조사 / 결과 열기 / 작업 진행 보기 |
| S06 새 조사 | Node, GPU 선택, 시작·종료 시각 KST, 증상 | 검증 후 접수 → job_id → S11 |
| S07 사건 결과 | 사건 범위, 사실, 후보, 지지·반박·누락, Runbook | 근거 열기, 추가 질문, 조치 기록, 재분석 |
| S07B 직접 요청 결과 | 요청 범위, 증상, 품질, 미확정 내용 | incident_id 없이 표시. 새 작업으로 재분석 |

입력 검증: 필수 대상·증상, 종료 > 시작, 허용 범위 안의 GPU, 사용자 권한, 증상 최대 길이 제안 2,000자. 클라이언트 오류는 해당 필드 옆에서 설명한다. 서버 검증을 다시 수행한다. 클릭 중복 방지와 Idempotency-Key를 함께 적용한다.

결과는 세 판단을 분리한다. 관계는 current_mapping / incident_time_mapping / same_node_only / unknown. 영향은 not_assessed / no_impact_observed / disruption_observed / recovery_observed. 원인은 undetermined / candidate / supported / confirmed다. 관계가 확인됐다고 원인이나 피해를 확정하지 않는다.

근거 패널은 evidence_id, 조회 조건·시각, 원본 위치, 지지/반박/미확인 역할, 문서·조회 정의 버전을 보여준다. 근거가 없으면 신뢰도 백분율을 만들지 않는다. 현재와 사건 시각의 Pod 관계를 구분한다.

R01-R09 기능 범위: 알려진 오류, GPU→Pod, Pod→GPU, 영향, 원인 불명, 반복 위치, 공통 범위, 현재 조치 대상, 회복 확인. 9개 별도 메뉴 대신 요청·결과 안의 조사 유형과 후속 행동으로 제공한다.

조치 기록은 실제 수행 내용·수행 시각·운영자·후속 관찰을 남긴다. 기록 저장 자체를 복구 성공으로 표시하지 않는다. 웹 시안의 기존 INC-0248은 고정 예시이며 새 요청 결과와 구분한다.

| S08 | 관측 / 할당·활동 / 반복 사건 / 에너지, 사실·이유·다음 행동 | 선택 범위 적용, 질의, 조치 기록, 보고서 요청 |
| S09 | 범위, 날짜, 실행 방식, 포함할 주제 | 검증 → 비동기 접수 → S11. 초안을 즉시 만들어진 것처럼 표시하지 않음 |
| S10 | 저장 범위·기간, 주제별 수치/보류, 근거·버전, 검토 의견 | 관측 이동, 보고서 질문, 검토 저장, 실제 개발에서 파일 내려받기 |

보고서 날짜는 사용자 입력 기준 시작일 00:00부터 종료일 다음 날 00:00 미만까지 KST로 해석하고 UTC로 변환한다. 시작일과 종료일이 같은 하루 보고서는 허용한다. 조회 구간은 [start, end)다. 날짜 기반 입력과 정확한 시각 입력을 혼용하지 않는다.

현재 할당 현황은 활동 지표 없이도 표시할 수 있다. 기간 할당 GPU·시간은 이력, 저활동 할당은 활동 시계열·유효 구간, 비용은 요율·귀속 정책이 더 필요하다. 에너지는 실제 소비전력 또는 누적 에너지와 기간으로 계산한다. 전력 제한을 소비전력으로 대체하지 않는다.

O01-O11 대응: 장비·노드 / 할당 / 저활동 / 불균형 / 사건 / 사건 작업 / 배치 대기·용량 / namespace·project / 에너지 / 전후 비교 / 품질. MVP 화면은 4개 주제 묶음으로 시작한다. 나머지는 같은 분석 상세 구조에 항목을 추가한다.

보고서마다 request context, run_id, policy/query/knowledge/model version, evidence refs를 저장한다. 전역 기간을 변경해도 이전 보고서 결과를 다시 계산하지 않는다. 재생성은 새 버전으로 남긴다. 사용자 검토는 보고서 ID별로 분리한다.

주간 일정은 timezone, weekday, time, scope, topic, enabled로 저장하는 후속 범위다. 시안의 정기 실행 선택은 설정 모양만 보여주며 예약하지 않는다. 실제 PDF 출력은 서버가 저장 결과의 동일 버전을 사용한다.

## 09. S11 작업 상태와 수명주기

| execution status | UI 라벨 | 행동 |
|---|---|---|
| queued | 접수 대기 | 대기 이유·접수 시각, 취소 요청 |
| running | 실행 중 | 조회 / 계산 / 모델 대기 / 추론 / 저장 단계 |
| retry_wait | 재시도 대기 | 다음 시도 예정, 시도 횟수, 원 요청 기한 |
| succeeded | 완료 | 저장된 결과 열기, 품질 별도 표시 |
| failed | 실행 실패 | 오류 이유, 보존 근거, 허용된 재시도 / 새 분석 |
| cancelled | 취소 완료 | 확정 상태, 보존 결과·근거 여부 |
| expired | 기한 만료 | 종료 이유, 새 요청으로 재분석 |

취소 요청은 cancel_requested_at 같은 별도 필드다. 요청 버튼을 누른 즉시 cancelled로 바꾸지 않는다. 취소·완료 경합은 서버의 최종 상태가 결정한다. 취소 완료도 GPU 추론의 물리적 즉시 중단을 보장하지 않는다.

자동 재시도는 같은 job_id의 attempt가 증가한다. 재분석은 새 job_id / run_id를 발급하고 parent_job_id 또는 parent_run_id를 남긴다. 브라우저에서 임의 재접수로 중복 작업을 만들지 않는다. 재시도해도 원래 absolute deadline은 늘어나지 않는다.

POST 요청은 DB에 내구적으로 저장한 뒤 202와 job_id를 반환한다. 결과와 evidence reference 저장이 끝나기 전에는 succeeded로 바꾸지 않는다. 브라우저를 닫아도 실제 작업은 유지되며 재진입 시 서버를 조회한다. 시안은 메모리에만 보관하고 수동 진행 버튼을 명시한다.

폴링 제안: 보이는 활성 작업 3초, 숨긴 탭은 15초 또는 일시정지, terminal 상태에서 중단. 서버 Retry-After·backoff를 우선하고, 네트워크 복구 시 동일 job_id를 조회한다. 이 값은 운영 부하와 맞춰 조정한다.

작업 큐 대기 / 공유 LLM 호출 대기 / 추론 소요를 분리한다. 확보하지 못한 Dynamo 내부 큐 시간·TTFT·토큰 속도를 추정 표시하지 않는다. 완료 예상률도 서버 근거가 없으면 단계 표현만 사용한다.

## 10. S16 공통 Assistant

Assistant는 모든 주요 화면에서 열 수 있지만 기본 화면의 중심은 업무 내용이다. 최초 진입에서는 닫힌 상태를 기본으로 한다. 데스크톱은 오른쪽 약 360px 패널, 좁은 화면은 오른쪽 drawer로 표현한다.

| 요소 | 계약 |
|---|---|
| 범위 칩 | 일반 질문 / 현재 화면 / 전체 시스템을 명확히 표시 |
| 현재 화면 적용 | 이후 메시지의 context만 변경. 과거 응답의 대상·시간은 유지 |
| 기본 자동 처리 | 개념·안내는 common, 전문 업무는 RCA / ops로 연결 |
| 고급 옵션 | 직접 Agent 지정은 접힌 대화 설정에 배치 |
| 응답 | 처리 주체, 내용, 품질, 근거, 저장 context, 사용 모델·버전 |
| 바로가기 | 허용된 화면 + 리소스 ID + 대상·기간을 전달. 임의 URL 실행 금지 |
| 긴 분석 | 접수 확인 카드와 job_id, 작업 이력으로 이동. 완료 후 결과 링크 |
| 대화 펼치기 | 동일 conversation_id로 넓은 작업 화면 S16 전환 |

일반 답변은 “운영 데이터 참조 없음”으로 표시한다. 실제 조회 없는 답변을 관제 결과처럼 보이지 않게 한다. 화면 설명과 실제 시스템 판단도 구분한다. 데이터 범위가 없으면 범위 적용을 안내한다.

실제 구현은 스트리밍 중 / 연결 끊김 / 중단 요청 / 재전송을 분리한다. 중단된 텍스트는 부분 응답으로 보존한다. 부작용이 있는 도구 실행은 메시지 재전송으로 중복 수행하지 않는다. Markdown은 안전한 렌더러로 출력하고 임의 HTML·스크립트는 허용하지 않는다.

시안은 고정 예시와 키워드 분기다. 자유로운 질의응답, 스트리밍, 실제 LLM 도구 실행은 아직 연결하지 않았다. UI에서 모델 지정이 바뀌어도 기존 응답의 모델 표시를 소급 변경하지 않는다.

## 11. S12-S15 지식과 연결 설정

| 화면 | 핵심 필드 / 동작 | 제한 |
|---|---|---|
| S12 지식 | Runbook·조사 절차·정책·참고 문서·검증 사례, 원문·발행 버전·조건 | 저장소의 원본과 DB의 발행 버전을 구분. 검증 사례는 검토 후 지식 개정 |
| S13 모델 | 이름, protocol, IPv4, port, base path, model ID | 등록·수정·삭제·형식 확인. 실제 연결 검사는 서버에서 수행 |
| S14 라우팅 | 공통 기본 / RCA / ops 모델, 공통 모델 상속 | 명시적 설정만 적용. 실패 시 외부 모델로 자동 우회하지 않음 |
| S15 데이터 | Mimir·Loki·KSM·매핑·업무 DB의 준비 상태, 관측 시각, 경로 | 연결 가용성과 분석 데이터 충분성을 별도로 표시 |

모델 필수값은 공백 제거 후 확인한다. IPv4는 4개 octet 각각 0-255, port는 정수 1-65535, protocol은 http/https, 경로는 /로 시작하며 ..와 // 등 모호한 경로를 차단한다. 모델 이름·ID·경로의 제안 길이는 100자 이하다. 실제 모델 지원 프로토콜과 /v1 호환 여부는 서버 검증 대상이다.

현재 시안은 브라우저 localStorage에 비밀값 없는 예시 설정만 저장한다. 실제 서비스는 관리자 API로 저장하며 비밀키는 서버 비밀 저장소에 보관한다. 등록된 IP·포트로 브라우저가 직접 접속하지 않는다. 연결 검사는 관리자 허용 네트워크·포트 목록 안에서 서버가 수행해 SSRF와 임의 내부망 스캔을 방지한다.

기본 또는 Agent에 지정된 모델을 삭제할 때는 대체 모델을 먼저 선택하게 한다. 연결 검사 실패를 모델 설정 삭제로 처리하지 않는다. “형식 정상”과 “통신 성공”은 다른 상태다. 다중 모델·Dynamo 경유 여부는 백엔드 구성으로 관리하며 프론트는 모델 별칭·활성 상태·허용 역할만 사용한다.

외부 Codex·Claude 연결은 이번 MVP에서 제외한다. 사용자 데이터의 외부 전송 정책이 정해졌을 때 별도 승인·전송 범위·감사 항목과 함께 검토한다.

## 12. 공통 데이터와 판단 계약

| quality | 표시 | 숫자 처리 |
|---|---|---|
| ready | 산출 가능 | 유효 근거·범위와 함께 값 표시 |
| partial | 부분 산출 | 산출된 범위만 표시하고 누락·제외 범위 설명 |
| blocked | 근거 부족 | value=null. 0·정상·미할당으로 대체하지 않음 |
| not_applicable | 적용 대상 아님 | 해당 장비·방식에 적용되지 않는 이유 표시 |

quality와 execution_status는 독립이다. 데이터 준비 부족은 서버 실행 오류가 아니다. 관측 지연도 장비 장애와 별도 축이다. 서버 실패로 수신하지 못한 값을 이전 캐시로 보여줄 때는 마지막 성공 시각과 현재 오류를 표시한다.

시간 저장은 UTC, 계산 구간은 [start, end), 기본 표시는 Asia/Seoul이다. 사건 발생 event_time, 원천 관측 observed_at, 수집 ingested_at, 조회 retrieved_at을 구분한다. 과거 유효 관계는 valid_from / valid_to로 표현한다. 현재 매핑을 과거로 확장하지 않는다.

coverage는 필요한 입력의 유효 구간 공통 교집합을 백엔드에서 계산한다. 브라우저가 소스별 coverage를 단순 평균하지 않는다. 원천·필드·장비별 유효 간격을 넘겨 마지막 값을 계속 유지하지 않는다. 동일 지표의 여러 소스가 있으면 백엔드의 대표값 선택과 출처를 따른다.

계산 결과에는 unit, scope, period, denominator, query_version, policy_version, evidence_refs, missing_inputs를 포함한다. 수치 계산·집계·상태 판정은 공통 백엔드 기능이 담당하고 LLM은 결과 설명과 등록된 추가 조회 선택을 담당한다.

## 13. 프론트엔드 구성 제안

현재 시안은 HTML/CSS/JavaScript 단일 파일이다. 메뉴 구조를 검증하는 동안 이 구성을 유지한다. 실제 API 연결 개발 시 React + TypeScript를 기본 제안으로 하되 기존 사내 표준이 있다면 따른다. 특정 프레임워크 채택은 이번 산출물의 확정 결정이 아니다.

| 공통 단위 | 책임 / 입력 |
|---|---|
| AppShell / MainNav | 메뉴·경로·권한, 전역 Assistant 배치 |
| ScopeBar / ContextChips | 대상·기간·timezone·context 원본 및 적용 버튼 |
| QualityBadge / ObservationBadge | 서로 다른 상태 축의 라벨·아이콘·설명 |
| MetricCard / SeriesPanel | value/unit/quality/coverage, 누락·지연 표현 |
| AssetPicker / MappingTable | 안정 ID, 선택 상태, 세 독립 축 |
| AnalysisSection / EvidencePanel | 사실·판단·한계·다음 행동·근거 링크 |
| JobStatus / JobDetail | 실행 상태·stage·attempt·기한·취소 요청 |
| AssistantPanel / Message / Shortcut | 대화·스냅샷·처리 주체·허용 목적지 |
| ModelForm / RouteForm | 검증·저장·오류·권한·미저장 변경 |

상태는 서버 리소스 / URL 조회조건 / 일시 UI 상태로 나눈다. 서버 리소스는 job, run, report, conversation, knowledge, model. URL은 화면·리소스 ID·조회 범위. 일시 UI는 패널 열림·입력 초안·펼침 상태다. 새 전역 상태 프레임워크는 필요가 확인될 때만 추가한다.

조회 키에는 tenant / cluster / target IDs / 시간 / 지표 / 정의 버전을 포함한다. 늦게 도착한 이전 범위 응답을 현재 화면에 덮어쓰지 않는다. 화면 이탈은 조회 요청만 취소하며 서버 분석 작업을 자동 취소하지 않는다.

## 14. API 경계와 호출 목록 제안

브라우저 → 사용자 Gateway → Backend API를 단일 호출 경계로 둔다. Mimir/Loki/DB/LLM/Dynamo는 브라우저의 직접 연결 대상이 아니다. 아래 경로는 /api/v1 접두사를 가진 제안이며 구현된 API 목록이 아니다.

| 메서드·경로 | 용도 / 반환 핵심 |
|---|---|
| GET /overview | 범위 요약, KPI, attention, quality |
| GET /assets, /assets/{id}/gpus | 안정 ID·표시 이름·관측·하드웨어 |
| GET /mappings, /observability/quality | 시점 관계, 품질·누락·적용 가능성 |
| GET /metrics/series | 단위·유효 구간·원천·coverage |
| GET /incidents, /incidents/{id} | 사건 목록·정규화된 사건 상세 |
| POST /investigations | 조사 접수, 202 job_id |
| POST /report-jobs | 보고서 접수, 202 job_id |
| GET /jobs, /jobs/{id} | 실행 상태, attempt, stage, 결과 refs |
| POST /jobs/{id}/cancel | 취소 요청 접수, 확정 상태는 재조회 |
| GET /runs/{id}, /reports/{id} | 저장 결과·context·버전·품질·근거 |
| POST /runs/{id}/reanalyze | 새 작업, parent 연결 |
| POST /runs/{id}/actions | 실제 수행 내용·시각 기록 |
| PUT /reports/{id}/review | 검토 의견·상태, 버전 충돌 처리 |
| POST /conversations, /conversations/{id}/messages | 일반 메시지·분석 접수 카드·안전한 바로가기 |
| GET /knowledge, /knowledge/{id} | 발행 버전·출처·적용 조건 |
| GET/POST/PATCH/DELETE /models[/{id}] | 관리자 모델 설정 |
| POST /models/{id}/check, PUT /model-routes | 서버 연결 검사·라우팅 설정 |

목록은 cursor와 limit, 안정 정렬을 사용한다. 조회 오류는 {code, message, request_id, retryable, field_errors}를 기본 제안으로 한다. 백엔드 자동 재시도와 사용자 재분석은 별도 계약이다. 수동 동일 작업 재시도 허용 여부는 서버가 can_retry로 알려주도록 협의한다.

## 15. 요청·응답 예시 계약

## 16. 로딩·빈 상태·오류·권한

| 상태 | 보여줄 내용 | 사용자 행동 |
|---|---|---|
| 최초 로딩 | 카드·표 스켈레톤, 조회 중 | 중복 실행 비활성, 다른 메뉴 이동 가능 |
| 정상 빈 목록 | 해당 범위의 결과 없음 | 기간·필터 변경, 새 조사 |
| 근거 부족 | 누락 입력·영향받는 분석·품질 | S04 확인, 근거 확보 후 재분석 |
| 관측 지연 | 마지막 관측과 경과 시간 | 데이터 경로 확인, 현재 판단 보류 |
| 부분 조회 실패 | 성공한 카드 유지, 실패 영역 표시 | 해당 영역 재시도 |
| 401 | 인증 필요, 초안 유지 | 재로그인 후 조회 복구 |
| 403 | 권한 부족, 민감 상세 비노출 | 허용 메뉴 복귀 / 관리자 문의 |
| 404 | 없거나 접근 불가 | 목록으로 이동 |
| 409 | 최신 버전과 변경 충돌 | 새 버전 조회 후 검토. 입력 덮어쓰지 않음 |
| 422 | 필드별 검증 오류 | 잘못된 입력으로 포커스 |
| 429 | 서버 대기시간과 요청 제한 | Retry-After 준수, 입력 유지 |
| 5xx / 네트워크 | 조회 실패, 마지막 성공 시각, request_id | 같은 조회 재시도. 분석 신규 접수는 중복 방지 |

역할 제안: 조회자는 관측·발행 결과를 읽는다. 운영자는 조사·보고서 요청과 자신의 검토·조치 기록을 수행한다. 관리자는 모델·라우팅·데이터 연결 설정을 관리한다. tenant와 cluster 범위는 서버가 항상 검증한다. 프론트 버튼 숨김은 권한 제어를 대체하지 않는다.

미저장 폼은 페이지 이탈 시 보존하거나 사용자에게 변경 손실을 알린다. 입력·검토 저장 실패 시 초안을 지우지 않는다. 오류 로그에는 토큰·원문 민감 데이터·내부 주소를 무분별하게 남기지 않는다.

## 17. 반응형·접근성과 시각 기준

| 폭 / 조건 | 제안 동작 |
|---|---|
| 1280px 이상 | 좌측 메뉴 약 180px, 본문 유동, 열린 Assistant 약 360px |
| 1051-1279px | 본문 카드 열 수 축소, 근거 패널 필요 시 접기 |
| 701-1050px | Assistant는 overlay drawer, 본문·설정 폼 단일 열 전환 |
| 700px 이하 | 메뉴 줄바꿈 또는 축약 메뉴, 표 내부 가로 스크롤, 카드 단일 열 |
| 터치 기기 | 주요 조작 최소 44px, 입력 글자 16px 권장 |

색만으로 상태를 전달하지 않는다. 라벨과 설명을 함께 둔다. 한 화면의 주 행동은 녹색 기본 버튼으로, 보조 행동은 테두리 버튼으로 구분한다. 본문은 약 14-16px, 부가 정보는 12px 이상을 기준으로 한다. 높은 정보 밀도가 필요한 표도 가독성을 우선한다.

키보드로 모든 조작에 접근하고 focus-visible을 제공한다. 화면 이동 후 제목에 포커스, drawer를 닫으면 열기 버튼으로 복귀한다. 실제 overlay는 dialog 의미·포커스 가두기·배경 inert·Escape 닫기를 구현한다. 데스크톱의 비모달 보조 패널은 포커스를 가두지 않는다.

Assistant 입력창은 패널 아래에서 보이도록 유지하고 메시지 목록만 스크롤한다. 320px 폭에서도 전체 페이지의 가로 넘침을 만들지 않는다. 큰 데이터 표는 표 컨테이너만 스크롤한다. prefers-reduced-motion을 따르고 상태 알림을 과도하게 반복 읽지 않는다.

시안의 명암 모드는 운영체제 선호를 따른다. 실제 구현 단계에서 WCAG AA 대비, 스크린리더, 확대 200%, 모바일 키보드가 열린 상태를 별도 검수한다.

| 단계 | 개발 항목 | 완료 판단 |
|---|---|---|
| P0-1 기반 | 인증·범위 권한, AppShell, URL 라우트, 공통 품질·오류 | 새로고침·뒤로 가기·권한 오류가 일관됨 |

새 라이브러리는 해당 기능이 필요한 시점에 도입한다. 표·폼·패널의 기본 구현은 재사용하고 단순 화면마다 별도 상태 프레임워크나 서비스 계층을 만들지 않는다. Backend 8개 논리 기능을 8개 프론트 모듈·배포 단위로 강제하지 않는다.

## 19. 인수 테스트와 시안 구현 차이

| ID | 시나리오 | 기대 결과 |
|---|---|---|
| AC01 | 대시보드에서 일반 개념 질문 | common 답변, 운영 데이터 참조 없음 |
| AC02 | GPU 선택 후 질문·바로가기 | GPU·대상·기간 유지, 과거 메시지 범위 불변 |
| AC03 | 지연 Node만 조회 | 마지막 값 구분, 현재 추이 판단 보류 |
| AC04 | 매핑 과거 시점 전환 | 현재 matched를 과거에 복제하지 않음 |
| AC05 | Pending + bound | 모순 없이 세 독립 축 표시 |
| AC06 | 보고서 접수 후 메뉴 이동 | S11에서 진행 확인, 완료 전에 새 결과 공개하지 않음 |
| AC07 | succeeded + partial / blocked | 실행 완료와 결과 품질 동시 표시 |
| AC08 | 취소 요청과 완료 경합 | 서버 최종 상태 우선, 요청 즉시 cancelled 금지 |
| AC09 | 동일 작업 재시도 / 재분석 | attempt 증가 / 새 job+parent 구분 |
| AC10 | 기간·라우팅 변경 후 옛 결과 열기 | 저장 context·버전·모델·검토 유지 |
| AC11 | 잘못된 IP·port·경로 | 필드 오류, 저장·네트워크 호출 방지 |
| AC12 | 스크립트 포함 질문 | 텍스트 표시, 실행되지 않음 |
| AC13 | 320px 및 짧은 화면 | 전체 가로 넘침 없음, 채팅 입력 가능 |
| AC14 | 새로고침·세션 만료·네트워크 복구 | 서버에서 작업 복구, 입력 초안 손실 방지 |
| AC15 | 과거 할당 이력 없는 GPU·시간 | blocked, value=null, 필요한 입력 표시 |

현재 웹은 AC01-06, AC08-09의 시뮬레이션, AC11-13의 화면 검증에 사용한다. AC07의 partial은 시안에 있고 blocked 완료는 실제 통합 테스트에서 추가한다. AC10의 전체 버전 고정·AC14의 서버 복구·권한 제어는 후속 개발이다. 시안만으로 운영 준비가 완료됐다고 판단하지 않는다.

시안 제한: 메모리 기반 작업·대화, 고정 예시 분석, 모델 설정만 로컬 저장, 실제 예약 없음, API·DB·LLM 없음. 모델 설정·작업 진행 버튼은 화면 검토 용도다. 실서비스 반영 시 시안 전용 조건 선택과 수동 진행 버튼을 제거한다.
