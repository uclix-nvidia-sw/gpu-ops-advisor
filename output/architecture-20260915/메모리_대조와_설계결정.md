# DSX 구조도 재구성 — 메모리 대조와 설계 결정

기준일: 2026-09-15. 이번 작업은 접근 가능한 프로젝트 대화, 공유 문서 사본, 최신 진행 기록을 대조해 구조도를 다시 구성한 것이다. 운영 클러스터 조회·설정 변경·모델 배포를 수행하지 않았다. 첨부 문서의 명령과 제안은 분석 자료로 취급했다.

## 유지한 서비스 계약

- **Grafana 직접 알림:** 관리형 규칙과 내장 알림 처리에서 Webhook을 Incident Aggregator로 전송. 별도 Loki/Mimir Ruler·Alertmanager 서비스는 추가하지 않는다.
- **사건 처리:** 원본 이벤트, Grafana 알림, Incident, 분석 실행은 별개다. 저장 성공 후 신규·재발·심각도 상승·판단에 영향을 주는 새 증거에서 RCA를 실행한다. 재전송 키·사건 상관 기준·분석 멱등 키를 구분한다.
- **읽기 전용:** Agent는 조회·분석·권고를 제공한다. 리셋·재부팅·Pod 종료·능동 진단은 운영자 실행 영역이다. 서비스가 자체 분석 DB에 결과를 저장하는 것은 이 원칙과 양립한다.
- **복구:** 유효 PASS reason, 데이터 최신성, 관측 범위, 정책의 연속 N회 성공을 확인한다. N은 운영 정책으로 확정한다. Healthy·검사 불가·데이터 없음·알림 resolved만으로 장비 복구나 작업 재개를 확정하지 않는다.
- **미해결 조사:** Runbook 정확 매칭에 실패해도 증상·대상·시점에 맞는 등록 조사로 진행한다. 범위·횟수·시간·응답량 한도를 지키고 부족·상충·실패·종료 이유를 남긴다.
- **재사용:** 실제 조치 결과와 검토가 확인된 사례만 KB 개정으로 연결한다. LLM의 후보·설명을 자동으로 확정 지식으로 승격하지 않는다.

## 데이터·식별·시간 기준

이벤트 원본의 `cluster_id + machine_id/host_name + component`와 발생 시각을 보존하되, 이를 모든 엔터티의 영구 키나 Incident 유일 키로 사용하지 않는다. 공통 기준 v1.0에 따라 Node는 cluster+node_uid 또는 검증된 노드 인스턴스 신원, GPU는 cluster+gpu_uuid와 시간별 Node 관계, Pod는 cluster+pod_uid를 사용한다. GPU index와 노드 이름만으로 과거 재생성·교체를 연결하지 않는다.

CPC-2의 동시점 소스 결합은 `cluster_id + node + uuid`, UID 보강은 같은 시점의 `cluster_id + namespace + pod + node`로 KSM uid를 결합한다. 이 성공이 전체 과거 이력의 정확성을 뜻하지 않는다. 원본 샘플 시각, 이름 재사용, 여러 UID, 지연·공백·짧은 작업을 검사하고 모호하면 귀속을 보류한다.

Pod 배치, GPU 매핑, GPU 활동을 서로 다른 축으로 관리한다. Pending 전체를 미배치 수요로 세지 않는다. UUID 없는 미배치 Pod가 수요 집계에서 사라지지 않도록 GPU 매핑과 inner join하지 않는다. 공유 GPU의 전체 활동을 여러 Pod에 각각 귀속해 합산하지 않는다. Namespace·node_group을 자동으로 프로젝트·부서·사람으로 치환하지 않는다.

기존 공통 기준 v1.0의 결측·기간·후보 정의는 변경하지 않았다. 일반 비교의 공동 커버리지 기본 진입 기준 95%, 저활동 후보의 60분 창·GPU utilization 5% 미만·유효 시간 90% 이상 등은 **후보 분석 정책**이며, 실제 수집 검증이나 회수 가능 확정값이 아니다. 현재의 약 14분 확인 구간으로 해당 60분·주간 결과를 제공 가능하다고 표시하지 않는다.

## 저장과 Local LLM 설계

Mimir와 Loki의 관측 이력은 저장소 API로 조회하며 Object Storage를 운영 보관 기반으로 둔다. Object Storage 추가가 현재 테스트 구성을 운영 내구성까지 갖춘 상태로 바꾸지는 않는다. 서비스 DB는 관계·사건·결과·핵심 근거와 버전을 보존한다. 필요한 근거 파일·공유 보고서 파일은 관측 데이터와 별도 버킷 또는 접두어·권한으로 보관할 수 있다. 원시 시계열과 전체 로그를 SQL에 다시 복제하지 않는다.

Mimir의 메트릭 블록은 Object Storage에 영속화할 수 있다. 보존 설정은 전역·tenant 기준이며 source 라벨만으로 같은 tenant의 시계열마다 다른 보존 기간을 지정할 수 없다. 따라서 Fleet 7일/Exporter 30일/집계 13개월 같은 카탈로그 제안은 이번 확정 구조에 넣지 않았다. [Mimir Object Storage](https://grafana.com/docs/mimir/latest/configure/configure-object-storage-backend/), [Mimir 보존 설정](https://grafana.com/docs/mimir/latest/configure/configure-metrics-storage-retention/)

Local LLM은 사내망 추론 Endpoint를 통해 공통 Assistant와 두 Agent가 사용한다. NVIDIA Nemotron 3 Super는 사용자 초기 후보로 유지하며 특정 GPU에 적재 가능하거나 현재 배포됐다고 가정하지 않는다. 모델 가중치·캐시 볼륨, 추론 GPU, 서빙 엔진·양자화·동시 요청 성능은 별도 확정한다. 같은 평가 사례로 정확도·근거·도구 사용·보고서 품질과 지연·처리량·VRAM을 비교한 뒤 소형 모델 전환을 결정한다. ## 산출물 검증

네 페이지의 글자 영역·라벨 겹침, 화살표의 노드 침범·중첩 경로·연결 끝점, SVG 접근성 및 16:9 출력 크기를 점검한다. 브라우저에서 PNG를 직접 확인한 뒤 제공한다. 외부 웹 폰트 로딩이 제한돼 PNG는 설치된 맑은 고딕·바탕 계열 대체 글꼴로 렌더링했다. SVG/HTML을 다른 환경에서 열면 폰트가 바뀔 수 있으므로 동일한 외형이 필요하면 PNG를 사용한다.
