# 01. 요구사항·개발 범위

버전 1.3 · 2026-09-17 · 개발 기준

## 목적

CPC의 GPU·Node·Pod 관측을 활용해 장애 원인 조사와 운영보고서를 제공한다. 판단·근거·데이터 한계를 함께 보여주며 실제 장비 조치는 사람이 결정하고 수행한다.

## 확정 구조

| 요청 | 생성 주체 | 실행 흐름 |
|---|---|---|
| RCA | Grafana 알람을 처리하는 Incident | Incident → Job Controller RCA 큐 → RCA Agent |
| 즉시 보고서 | GUI 요청을 받은 Backend | Backend → Job Controller 보고서 큐 → 보고서 Agent |
| 정기 보고서 | Backend 내부 일정 기능 | Backend → 동일 보고서 큐 → 보고서 Agent |
| 결과 조회 | GUI | Backend → 저장된 사건·결과·근거/큐 상태 |
| Agent 용량 변경 | 운영자 | 배포 수·동시성·공유 추론 한도 수동 변경 |

Job Controller는 가용 슬롯 안에서만 잡을 배분한다. 슬롯이 없거나 해당 종류의 Agent가 없으면 대기한다. 큐 대기는 실행 실패가 아니며, 명시된 deadline을 넘으면 expired다.

## 기능 요구사항

| ID | 요구사항 | 완료 조건 | 우선 |
|---|---|---|---|
| F01 | 자산·관측 조회 | CPC/Node/GPU/Pod 식별·기준 시각·품질 표시 | P0 |
| F02 | 알람 사건 처리 | 중복 알람에 사건/동일 RCA 잡 중복 생성 없음 | P0 |
| F03 | RCA 실행·결과 조회 | Incident 기원만 접수, R01~R09 근거·한계 보존 | P0/P1 |
| F04 | 즉시 보고서 | O01~O11 선택·접수·저장 결과 조회 | P0/P1 |
| F05 | 정기 보고서 | Backend 일/주/월 발생·중복 방지·복구 | P0 |
| F06 | 영속 큐·잡 배분 | 유형별 큐, 가용 슬롯, 공정성, 재시작 내구성 | P0 |
| F07 | 상태·실패 복구 | lease, 제한 재시도, 취소, stale 완료 차단 | P0 |
| F08 | 결과·출력 | 사실/수치/근거/설명 상태 분리, HTML/CSV 일치 | P0 |
| F09 | 지식·모델 설정 | 불변 발행 revision·호환성·RCA/보고서 모델 지정 | P1 |
| F10 | 운영 검토 기록 | 검토/실제 조치를 별도 기록, 자동 장비 조치 없음 | P1 |
| F11 | 운영·수동 용량 조정 | 제한값 검증·drain·복구·백업 시연 | P0 |

P0는 대표 R/O 흐름·계산·실행 기반을 먼저 연결하는 순서다. 전체 R01~R09/O01~O11은 개발 범위이며, 데이터가 없는 주제는 blocked/partial과 이유를 반환한다. 입력 미확보를 해당 기능 구현 완료로 처리하지 않는다.

## 비기능 요구사항

| ID | 기준 |
|---|---|
| N01 | 관측과 추론 분리: 계산은 코드, 설명은 LLM. 0과 null 구분 |
| N02 | 내구성: 접수 커밋 이후 잡 보존, 같은 멱등 키로 한 잡, final 한 개 |
| N03 | 용량: Worker·유형·공유 추론 한도 초과 금지. 무한 재시도 금지 |
| N04 | 추적: request/job/attempt/incident/occurrence/evidence ID·버전 연결 |
| N05 | 사용성: 처리 대기·데이터 부족·설명 실패를 서로 다르게 표시 |

## 제외 범위

Chatbot/대화 API·S16, GUI의 수동 RCA 실행/재분석·S06/S07B, 독립 달력 Scheduler, HPA와 자동 레플리카/노드/GPU 증설, 제품 로그인·RBAC·사용자 tenant 설계는 제외한다. scope는 조회할 CPC/Namespace 필터이며 권한이 아니다.

GPU reset·Node 재부팅·Pod 종료·자원 재배치·전력 제어·과금 확정·Run:ai 신규 연동·Exchange/NATS 신규 도입은 하지 않는다. 기존 수집 기반과 내부 서비스 접근에 필요한 환경 설정은 운영 설정으로 유지한다.

## 개발 단계

| 단계 | 산출·종료 조건 | 선행 조건 |
|---|---|---|
| 1 실행 기반 | 03/10/14 구현, 병렬 claim·stale 완료 시험 | DB·수동 용량 프로필 |
| 2 사건/보고서 | Incident·두 Agent 대표 흐름 및 저장 결과 | 1, 관측 표본·추론 endpoint |
| 3 GUI/정기 실행 | 조회·즉시/정기 보고서·작업 상태·출력 | 2, Backend 일정 |
| 4 업무 완성/인계 | R/O 전체·운영 설정·복구·데이터별 활성 원장 | 3, 실환경 증거 |

날짜·소요 주수는 미확정이다. 환경 입력과 담당자가 확정된 뒤 단계별 종료 조건을 기준으로 계획한다.
