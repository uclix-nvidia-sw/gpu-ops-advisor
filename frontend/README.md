# Frontend

GPU Ops Advisor의 React·TypeScript 화면이다. 모든 관점은 같은 Backend API와 저장 결과를 사용한다. 화면 전환은 권한이나 실행 경계를 바꾸지 않는다.

## 다섯 가지 GUI 탭

상단 순서는 **통합 콘솔 / 신규 콘솔2 / 개발자 / 신규 / 개발 콘솔**이다. `gpu-advisor-view`에 선택을 저장하며 기본값은 `classic`(통합 콘솔)이다. 신규 콘솔2는 기존 `operations` 저장값을 사용한다. 예전 운영 콘솔 저장값 `control`과 알 수 없는 값은 통합 콘솔로 연다.

| 관점 | 저장값 | 주 용도 |
|---|---|---|
| 통합 콘솔 | classic | 기존 관점과 운영 콘솔을 합친 기본 화면: 운영 대시보드·RCA 조사·Ops 보고서·지식 Runbook·자산·관측·연결·설정 |
| 신규 콘솔2 | operations | 기간별 운영 개요, 사건 검색·RCA 읽기, 요약·목차·그래프가 연결된 Ops 보고서 |
| 개발자 | developer | 처리 흐름·작업·원본 기록 |
| 신규 | new | 사건·보고서 중심의 결과 읽기와 기록 |
| 개발 콘솔 | workbench | 실패 작업 탐색, 입력→시도→근거→발행 결과 대조 |

통합 콘솔의 좌측 메뉴는 **운영 대시보드(`/dashboard`) · RCA 조사(`/cases`) · Ops 보고서(`/reports`) · 지식·Runbook(`/knowledge`) · 자산·관측(`/fleet/assets`) · 연결·설정(`/settings/...`)** 순서다. 대시보드·RCA 조사·RCA 장애 보고서(`/analyses/:id`)·사건 상세·지식·자산·설정은 기존 관점 화면을, Ops 보고서 목록·상세·작성(`/reports...`)과 자동 보고서(`/schedules`)는 예전 운영 콘솔 화면을 그대로 쓴다. 작업 이력 목록 메뉴는 없고 `/jobs`는 `/cases`로 보낸다. RCA 보고서의 ‘작업 상태·시도 이력’과 실행 중 RCA 링크가 여는 작업 상세(`/jobs/:id`)는 유지한다. 사이드바·상단 선은 운영 콘솔의 검정·녹색 테마를 따른다.

[ConsoleWorkspace](src/pages/ConsoleWorkspace.tsx)는 통합·개발 콘솔의 목록과 진입 동선을 소유한다. [Console2](src/pages/Console2.tsx)는 신규 콘솔2의 개요·사건 목록·보고서 목차를 담당하고, 기존 목록·결과·작성·일정 컴포넌트를 재사용한다. [Shell](src/components/Shell.tsx)은 메뉴·관측 범위·연결 상태를, [JobDebug](src/components/JobDebug.tsx)는 개발 콘솔의 상세를, [NewWorkspace](src/pages/NewWorkspace.tsx)는 결과 읽기·기록을 담당한다. 통합·개발자·신규·개발 콘솔의 기존 구성은 유지한다.

### 신규 콘솔2

주 메뉴는 운영 대시보드·RCA 조사·운영 보고서·지식·Runbook·연결·설정의 5개다. 브랜드 아래의 ‘운영자’는 현재 표시용 문구이며 인증·권한 분기가 아니다. 기존 자산·관측은 연결·설정의 ‘저장 관측 자료’로 연결하고 `/fleet/...` 경로를 유지한다. 실시간 인벤토리·장비 건강도로 해석하지 않도록 저장 자료의 의미와 빈 목록의 연결 확인 동선을 제공한다. 다른 콘솔의 메뉴·기능은 바꾸지 않는다.

대시보드는 사건 집계·RCA 보고서 생성 상태·일별 누적 막대 추이·유형별 도넛 분포를 먼저 보여준다. 그래프의 날짜와 유형을 선택하면 해당 RCA 사건으로 이동한다. 저장된 Ops 보고서 요약은 사건·반복·노드 분포 다음에 별도 영역으로 표시하며 그래프를 기본으로 펼친다. 사건 기간과 독립적으로 보고서 하나를 선택한다. 불러온 성공·발행 보고서를 분석 종료일 최신순으로 표시하며 추가 페이지는 더 불러오기로 조회한다. 제목·분석 기간·저장 범위·결과 품질과 원본 링크를 제공한다. 실시간 관측이 아니며 보고서들을 합산하거나 결측을 0으로 바꾸지 않는다.

검정 사이드바·회색 본문·녹색 선택 강조를 사용한다. 브랜드는 제공된 그림에서 분리한 거북이 마크를 사용하고 기능 없는 WORKSPACE·콘솔 번호 장식은 제거한다. 운영 개요는 오늘·7일·14일·30일의 저장 사건과 오늘 발생 건수, 최신 실행 상태, 같은 클러스터·노드·장치·오류의 3회 이상 반복, 부분 산출·판단 보류 건수와 최신 6건을 보여준다. 날짜·반복 대상·노드·숫자 카드는 RCA 조사로 연결한다. 현재 장애·복구·장비 건강도를 추정하지 않는다. 서비스 응답 상태와 저장 Ops 사용 관측은 구분한다.

RCA 조사는 전체 기간을 기본으로 열고, 표시된 노드 이름·오류·PCI·알림 내용 검색, 클러스터·노드·장치 유형·실행 상태·공개 결과 품질·오류 유형 필터와 날짜 달력을 제공한다. 대시보드에서 선택한 기간과 사용자 지정 날짜를 유지하며, 선택 범위·기간의 최대 1,000건을 불러와 25건씩 보여주고 검색 범위와 한도를 명시한다. URL 조건과 상세에서 돌아온 선택 행을 복원한다. 공개 RCA가 있으면 고정 분석본으로, 없으면 사건 상세로 연결한다. 최신 실행의 대기·실행 중·재시도 대기·완료·실패·취소·만료는 공개 결과 품질과 별도로 표시한다. 새 실행 중에도 이전 발행 보고서를 열 수 있다. 알림 수신/해제 상태는 모든 관점의 목록·상세·대시보드·보고서 주요 표시에서 제외하며 과거 저장값과 원본 확인은 보존한다. 사건·대상 장비·런북 참고·보고서·발생 시각을 별도 열로 표시한다. 신규 콘솔2 목록은 사건 열을 넓히고 장비·보고서 열을 줄여 긴 오류 이름도 셀 안에서 줄바꿈한다. 사건 이름과 PCI·UUID는 수신 alert에서 추출하며 런북 이름으로 바꾸거나 인벤토리 모델을 추정하지 않는다. 런북 안내는 일반 참고이며 RCA 결론·수행 기록과 구분한다. 행 펼침은 추가 API 요청 없이 원문·컴포넌트·UUID·런북 순서를 보여준다. 기본 필터는 노드·실행 상태·정렬이고 나머지는 추가 필터에 두되 적용 조건은 접어도 표시한다. 최신순·오래된 순·장치별·오류별 정렬과 선택 기간의 유형 분포, 누적 막대 추이, 노드별 유형 건수를 제공한다. 반복 탐색은 장치별·오류별·최근 발생순이며 정확한 코드 또는 클러스터·노드·장치·코드 조합으로 이동한다. 잘못된 날짜 URL은 기본 기간으로 처리한다.

RCA 보고서는 해당 사건의 대상·시각을 앞에 두고 관측 비교와 사실·후보·한계·다음 확인을 구분한다. 신규 콘솔2의 관측 비교는 해당 alert의 원본 이벤트·첫/마지막 로그·지표 비교 기준을 같은 시간축에 놓고, 저장된 지표의 사건 전후 최솟값·최댓값·마지막 값과 표본 수를 비교한다. 연속 시계열이나 장애 지속 시간은 추정하지 않는다. 작은 차이를 확대하는 수치 축은 관측 범위에 맞췄음을 표시한다. 상태 코드는 수치 막대 대신 상태 문구로, 전체 구간만 저장된 지표는 전체 구간으로, 누락·유효하지 않은 표본은 미확인으로 표시한다. 이력의 날짜별 막대는 기존 기간·장치·코드 필터와 연결하고 KST 기준 Incident ID별 건수를 센다. 일부 저장 이력과 조회 경계일의 한계도 표시한다. 긴 관련 관측은 펼쳐 읽고 원문 근거를 열 수 있다. RCA·운영 보고서의 목차는 본문 왼쪽에 고정하며 모바일에서는 상단 선택 메뉴로 바뀐다. 사건 상세의 조사 이력·처리 상태도 목차로 이동한다. Ops 목록은 저장 요약을 접고 분석 범위를 간결하게 표시해 탐색 밀도를 높인다. 상세는 Namespace·GPU 모델별 활동률/메모리 비교 막대와 이전 기간 대비 사건 수를 먼저 보여주고 시간대별 그래프, 저장된 해석과 적용 조건, 상세 표로 이어진다. 비교 가능한 이전 활동률만 점선으로 표시하며 모델 평균을 임의로 합치지 않는다. 수치 미확인 기록은 0%와 구분해 별도로 펼쳐 확인한다. 저장된 해석을 별도 요약 카드에 중복하거나 접어 숨기지 않는다. 제안 대상·구간의 그래프 강조와 읽던 제안 복귀를 제공하고, 넓은 화면에서는 활동률·메모리를 나란히 비교한다. Namespace 선택은 신규 콘솔2의 두 그래프에 함께 적용하며 유효 관측이 없는 그래프는 자료 부족 설명으로 대체한다. 다른 콘솔의 그래프 선택은 기존처럼 독립적이다. 강조는 원래 값·표본 공백·CSV 계산을 바꾸지 않는다. HTML·CSV 다운로드와 현재 화면 HTML 저장, 기존 작성·검토·일정 명령을 유지한다. 입력은 탭 전환 시 확인하고 임시 저장하며 성공한 요청의 초안은 지운다. 지식 목록은 발행된 Runbook을 기본으로 열고 분류를 간결한 필터 버튼으로 표시한다. 오류·미등록·검색 결과 없음·미발행 결과를 구분한다.

개발 콘솔의 `/dashboard`는 실패 작업으로 시작하고 `/jobs`는 전체 작업을 보여준다. 작업 종류·실행 상태·노드 이름 또는 UID·사건 ID·접수일을 서버에서 검색하며 작업 ID로도 바로 연다. 목록에서 단계·종료 사유·시도를 확인하고, 선택한 작업의 진단 패널에서 고정 입력·시도 비교·근거·발행 결과로 이동한다. 미발행 결과는 표시하지 않는다. 필터를 바꾸면 이전 작업 선택을 해제하며 상세를 방문한 뒤에는 URL의 검색 조건과 선택 작업으로 복귀한다. Ops 작업은 보고서 제목과 분석 범위로 표시한다.

Ops 목록은 선택한 날짜와 분석 기간이 겹치는 보고서를 찾는다. 상태·주제·요청 접수일은 보조 조건이며 분석 기간만, 보조 조건만, 모든 조건을 각각 해제할 수 있다. 저장된 주요 변화와 관측·해석 한계를 먼저 보여주고, `method`·`narrative_status`에 따라 AI 해석·AI가 고른 변화·계산 요약을 구분한다. 생성 방식이 확인되지 않으면 ‘저장된 주요 변화’로 표시한다. 발췌 여부를 알리고 전체 본문으로 연결한다. 작성 중·삭제된 결과는 작성 현황·삭제 기록으로 연결하며 일부 목록을 전체 건수나 클러스터 건강 점수로 표시하지 않는다.

통합 콘솔의 `/dashboard`([OperatorDashboard](src/pages/OperatorDashboard.tsx))는 최근 14일(KST 첫날 0시부터) 사건(`/incidents`, 200건씩 최대 5쪽)을 [incidentOverview](src/lib/incidentOverview.ts)로 계산한다. `/cases`([OperatorCases](src/pages/OperatorCases.tsx), 제목 RCA 조사)는 같은 계산을 선택한 기간에 적용한다. 기간은 오늘·7일·14일·30일·전체(기본) 버튼이나 [범위 달력](src/components/RangeCalendar.tsx)(시작일→종료일, 같은 날 두 번이면 하루, 미래 날짜 불가)으로 고르며 URL `period` 또는 `from`·`to`(KST 포함 날짜)에 저장한다. Backend `/incidents`의 `from`·`to`(발생 시각, 끝 제외)로 조회하고, 불러온 사건은 화면에서 50건씩(장치별·오류별 정렬은 20묶음씩) 페이지를 나눈다. 기간 안 사건이 1,000건을 넘으면 일부만 불러왔다고 알리고 기간을 좁히게 한다. 사건마다 수신된 오류 코드·설명·장치(PCI/UUID)·같은 클러스터와 장치의 반복 횟수·런북 안내·RCA 보고서 링크를 한 줄로 보인다. 첫 발생의 반복 배지는 생략한다. 발행된 RCA가 있으면 제목과 ‘보고서 열기’가 모두 RCA 장애 보고서(`/analyses/:id#final-report`)를 열고, 보고서의 ‘목록으로’는 같은 기간·페이지로 돌아온다. 발행 RCA가 없는 사건의 제목은 링크가 아니다. 발생·해제 배지와 필터·집계는 표시하지 않는다. firing만 한 번 수신하는 환경에서 경과 시간이나 해제 알림 부재로 현재 장애 지속·복구를 추정하지 않는다. 하루 지난 사건도 기본 목록에 유지하며 대시보드·필터·노드 집계는 수신 기록 기준이다. 날짜는 `2026.10.26. (월)`로 묶고 최신순·오래된순·장치별·오류별로 정렬한다. RCA 결과 품질(산출 가능·부분 산출)은 목록에 표시하지 않고 보고서에서 읽는다. 대시보드의 저장 사건 목록은 300px 안에서 스크롤하며 전체 펼침·높이 제한 복귀를 지원한다. 대시보드는 숫자 카드, 분류별 도넛(오늘·14일), 건/일 단위의 14일 추이, 저장된 사건, 장치별·에러별·시간별 반복 장치, 노드별 현황을 보여준다. 제목 바로 아래의 ‘GPU 사용 현황 · Ops 보고서’([OpsUsage](src/components/OpsUsage.tsx))는 `namespace_usage` 주제가 있는 최근 성공 보고서(`/reports?status=succeeded`) 하나의 저장 결과에서 Namespace별 평균 활동률(분석·비교 기간 막대), 시간대별 활동률(상위 3개 선), 연결 GPU 분포(도넛), 대기 Pod 최대(막대)와 기간 내 알림 수를 그린다. 활동률이 없는 행은 0%가 아니라 관측 부족으로 따로 적고, 보고서가 없으면 만들기 안내를 보인다. 분류는 GPU 자체·GPU 간 연결(NVSwitch·NVLink)·네트워크·서버다. 글꼴·색은 RCA 보고서와 같고, 위험은 글자색이 아니라 점·왼쪽 막대로 표시한다. 참고 안내·단계는 런북에서 생성한 [incidentLabels.json](src/lib/incidentLabels.json)(`python tools/generate_incident_labels.py` 후 `npm run format`)을 쓴다. XID/SXID 제목은 수신 원문의 설명을 사용한다. 단, 고정 Fleet·GPUd 카탈로그의 Reserved 17종·수집기 Unused 15종과 NVIDIA 공식 카탈로그의 Unused 63종(중복 제외 78종)은 수신 설명이 Reserved·Unused일 때 검수한 공식 정의의 운영자용 이름을 표시한다. XID 14는 시험용 오류 주입, XID 108은 즉시 조치 없음과 XID 137 조사 연결을 구분한다. 공식 미사용 코드는 부품 오류 이름을 만들지 않고 미사용 코드로 표시한다. XID 144~150의 세부 코드와 err status는 제목에서 분리하고 원문에 보존하며, 0값을 정상 판정으로 바꾸지 않는다. 기본 안내 13종과 조건별 절차는 구체적인 확인 대상·조건을 표시한다. 검색은 서버에 저장된 원문을 대상으로 하므로 새 번역 이름은 XID/SXID 번호로 검색한다. RCA 보고서의 한눈에 보기·참고 자료도 검수한 공식 의미와 제품 적용 범위를 표시하며, 저장 당시 설명은 별도 원문 펼침에 보존한다. 이 표시 보완은 저장 결과·로그·판정·조치 이력을 변경하지 않으며 Ops 보고서에는 적용하지 않는다. XID 173의 저장 RCA도 NVIDIA 공식 드라이버의 고정 코드 정의를 출처로 연결하며 이전 설명을 보존한다. 설명이 함께 있으면 기계 식별자는 접힌 원문에 두고, 식별자만 있으면 그대로 보존한다. 코드 외 설명이 없으면 코드만 표시한다. 코드·ID는 RCA 보고서와 같은 JetBrains Mono를 쓴다. Ops 보고서의 저장 서술·수치·범위는 유지하고, 알림 발생/해제 상태 열과 집계만 주요 표시에서 제외한다.

코드명·오류 이름·제목 검색은 URL `q`에 보존하여 Backend에서 날짜·scope와 함께 전체 사건을 검색한다. 코드 공백·콜론과 대소문자를 무시한다. 최신 실행이 대기·실행·재시도·실패·취소·기한 만료이면 해당 상태 버튼으로 실행 상세를 열고 이전 발행 결과 링크를 유지한다. 실행 성공이지만 결과가 없으면 실행 완료·미발행으로 구분한다.


두 콘솔은 검정·회색 바탕과 녹색 강조, 얇은 구분선과 표를 사용한다. 상태는 색상과 글자를 함께 제공한다. 좁은 화면은 메뉴를 접고 긴 표 안에서 스크롤하며, 선택 범위와 다섯 관점 전환은 유지한다.

RCA 워크플로우 디버깅의 **산출 상태·누락 사유 확인**은 새 결과의 `rca_status_decision`, 이전 결과의 `rca_result_frozen`으로 이동한다. 새 Worker는 수집 직후 `collection_assessment`에 실제 실행한 조건식·입력·분기 결과·함수·누락 사유를 남기고, 분석 후 `rca_status_decision`에 지침별 상태와 최종 `missing_inputs`·`result_status`를 남긴다. 화면은 이를 별도 코드 판단 단계로 표시하고 연결된 수집 원문과 자료 고정 기록을 오갈 수 있게 한다. `true/false`는 조건 성립 여부이며 장비 정상/고장 판정이 아니다. 이전 보고서는 저장된 판정값만 표시하며, 독립 실행 기록이 없는 조건별 입력이나 코드 버전을 추정하지 않는다. 현재 조건식 참고는 당시 실행 기록과 구분한다.

지식·Runbook은 발행됨을 기본으로 연다. 기존 목록 위에 저장된 `content.search`·`classification` 기준의 XID·SXID·OS·Memory·Disk·Network 현황을 표시하고, 해당하지 않거나 분류 근거가 없으면 기타로 보인다. 분류는 중복될 수 있으며 현황은 Runbook ID별, 목록은 revision별이다. 현황은 검색·발행 상태와 별도로 현재 범위의 발행 Runbook을 센다. 분류 선택은 기존 상태·종류·검색 조건을 유지하고, 선택 해제 버튼은 선택 중에만 나타난다. 200건씩 최대 20쪽을 자동 조회하며 추가 자료가 있으면 건수에 `+`와 안내를 표시하고 더 보기를 제공한다. 카드의 기존 상세 열기를 유지하며 제목·분류·revision·범위를 정렬하고 설명은 두 줄로 제한한다. 현황은 넓은 화면에서 한 줄, 좁은 화면에서 줄바꿈한다.

## 실행

Node 24와 저장소 lockfile을 사용한다. 먼저 [Backend 로컬 실행](../backend/README.md)의 격리 DB와 API를 준비한다. 개발 서버는 migration·예시 seed를 실행할 수 있으므로 공유/운영 DB의 `DATABASE_URL`을 사용하지 않는다.

```powershell
cd frontend
npm ci --ignore-scripts
npm run dev
```

개발 주소는 http://127.0.0.1:5173/dashboard 이며 Vite가 `/api`를 `127.0.0.1:8080`으로 전달한다.

```powershell
npm run format:check
npm test
npm run build
```

실행 증거와 미검증 범위는 [QA](QA.md), 화면 계약은 [07 개발 명세](../docs/specs/frontend/07_프론트엔드_개발명세서.md)·[08 화면 설계](../docs/specs/frontend/08_GUI_화면설계서.md)를 따른다.

## 연결과 명령

- `/clusters`의 CPC·Namespace가 공통 범위다. 클러스터가 없으면 등록을 안내한다. 연결·설정과 지식 관리는 빈 설치에서도 접근할 수 있다.
- 사건 발생일·작업 접수일·보고서 분석 기간을 구분한다. 통합 콘솔 RCA 조사는 사건 발생일 기간으로 조회한다. 보고서 분석일 검색은 저장된 `time_range`와의 겹침이며 접수일 검색과 독립적이다. 기존 관점의 보고서 접수일 검색은 유지한다. 상세의 범위·기간은 생성 당시 값이며 전역 기간으로 재계산하지 않는다.
- 자산·Pod 관계는 저장 관측이다. 등록 성공이나 서비스 readiness를 실제 수집·모델·분석 성공으로 표시하지 않는다.
- RCA는 Incident가 접수한다. GUI는 사건 메타데이터, 보고서 요청, 일정, 검토와 실제 수행 조치 기록을 기존 API로 처리한다. Worker 직접 호출·장비 제어는 없다.
- 명령은 기존 `If-Match` 버전과 멱등 키를 사용한다. 연결 오류·409·자료 부재를 성공으로 숨기지 않는다. 재시도는 동일 본문에 동일 키를 재사용한다.
- 삭제는 현재 상태·참조 보호·사유·버전을 확인하고 완료 전에 목록에서 지우지 않는다. 사건 원본·발행 Runbook·과거 결과를 화면 전환 때문에 수정하지 않는다.
- 입력 중 관점을 바꾸면 이탈 확인을 제공한다. 신규·운영 콘솔의 보고서/기록/일정 초안은 탭 저장소로 복원한다. 사건 기록 저장과 검토 상태·처리 상태 변경은 별도 명령이다. RCA 분석별 이전 기록은 원래 job에 남겨 읽기 전용으로 보존하고 새 사건 기록과 섞지 않는다. 복귀 경로는 허용된 앱 내부 경로만 사용한다.
- HTTP NodePort에서도 브라우저 SHA-256과 `crypto.getRandomValues`로 fingerprint·UUID를 생성한다. 비밀·본문·쿼리 값을 API 관찰 기록에 저장하지 않는다.

[Backend API](../backend/API.md)가 필드·상태·명령 계약의 기준이다.

## RCA 결과와 근거

현재 Worker는 **수집 1회 → 통합 분석 작성 → 최종 보고서 작성 → JC 발행**이다. 독립 검토 LLM·목표 판정·추가 수집 루프는 현재 실행 경로가 아니다. [RCA README](../rcca-agent/README.md)가 재시도·검증·기본 보고서 규칙을 소유한다. 과거 결과의 review/goal/selection 진단은 저장된 기록으로 읽으며 새 실행에 없는 단계를 만들지 않는다.

RCA의 한눈에 보기는 같은 노드 다른 오류만 한 줄 요약과 상세 펼침으로 묶는다. 한눈에 보기의 펼친 오류 목록은 원형 순번을 표시한다. 펼친 목록은 반복되는 제목과 대상 제외 안내를 한 번만 표시하고 코드·장치와 관측 내용을 나눠 읽는다. Q1의 오류 로그 장치 일치 판단은 항상 보이고 대조에서 제외한 오류만 ‘다른 오류 목록’에 항목별 줄바꿈으로 표시한다. Q4의 다른 오류는 코드별 사건 수 표를 펼쳐 읽는다. 세부 오류는 240px 안에서 스크롤한다. 통합 콘솔 RCA의 사건 타임라인은 최대 160px, 오류 로그는 최대 200px로 표시하며 펼침을 추가하지 않고 내부 스크롤로 모든 근거를 보존한다. 다른 관점의 타임라인 260px·오류 로그 320px는 유지한다. 기존 폰트·하이라이트·번호 구조와 대응 순서는 유지한다.

RCA 헤더와 로그 요약은 마지막으로 기록된 오류 시각을 보여준다. 마지막 기록이 분석 종료에 가깝다는 이유로 ‘보고 중’이나 복구를 추정하지 않는다. 오류 시각이 없으면 미확인으로 표시한다.

RCA 운영자 문구는 확인한 사건·수치·시각·대상을 먼저 제시하고 필요한 대응을 바로 이어 쓴다. 막연한 “모른다·미확인·확인하지 못했다”의 반복 대신, 수집 상태와 적용 조건을 구체적으로 표시한다. 표본 부족과 지표 미지원은 구분하며, 부족한 근거를 정상·복구로 표현하지 않는다. 기존 보고서 구성·형식과 통합 콘솔 폰트는 유지한다.


RCA 본문은 main의 여섯 구역(한눈에 보기·대응 순서·로그와 지표·분석·이력·참고 자료)을 유지한다. 통합 콘솔은 기존 RCA 장애 보고서의 폰트·6단 구성·내용 순서를 유지한다. 제목·안내 아래의 여섯 장 목차만 화면 상단에 고정하고, 제목·안내는 본문과 함께 스크롤한다. 좁은 화면의 목차는 한 줄 가로 스크롤이며 각 링크는 제목이 목차에 가려지지 않도록 해당 장으로 이동한다. 3장 안쪽 로그·지표 영역의 중복 여백을 제거해 다른 장과 시작선을 맞춘다. 이 변경은 통합 콘솔 RCA에만 적용되며 Ops 보고서에는 적용하지 않는다. 신규 콘솔2는 관측 비교와 판단 요약(`decisionSummary`: 확인한 사실·원인 후보·확인하지 못한 사항·다음 확인)을 앞에 두며, 기존 여섯 구역과 근거 원문을 유지한다. 다른 관점에는 이 요약과 시각화를 추가하지 않는다. 가져오지 못한 보조 지표(`quality.optional_unavailable`)는 확인하지 못한 사항에 지표 이름으로 표시하고 판단에 쓰지 않았다고 안내한다. 안내는 선택된 발행 Runbook의 의미·확인 순서·출처·한계를 사용한다. 일반 오류에 XID/SXID 전용 내용을 적용하지 않는다. 2장에서 물리 작업을 지시하는 런북 단계 아래에는 점검 위치 그림(SXM·PCIe 예시)을 작은 미리보기로 붙인다. 고르는 기준과 대상 단계는 [점검 위치 그림 설명](../docs/rca-animations/README.md#보고서-연결-구현)을 따른다.

- 오류 발생 시각, 상태 보고 시각, 알림 시작(`startsAt`)을 구분한다. 알림 시작을 수신 시각이라고 표시하지 않는다. 반복 보고 수는 장애 횟수가 아니다.
- GPU UUID·PCI를 줄이지 않고 원본 식별자를 보존한다. 인벤토리 대조·보고된 관계를 물리적 검증이나 현재 고장 확정으로 바꾸지 않는다.
- gauge는 사건 전후 값을 비교하며 검증된 임계값 없이 정상·변화 없음을 단정하지 않는다. 0 표본만으로 작업 중단을 판단하지 않는다. 누적값 감소는 재설정·대상 변경 확인 대상으로, enum/bitmask는 코드 변화로 표시한다.
- 작업의 관측 시작과 끝이 사건 시각을 포함할 때만 당시 관측으로 표시한다. 결측과 0, 수집 간격 안의 지연과 이후 수집 단절을 구분한다.
- 호스트 이력은 저장된 기간·조회 한도·대상·코드 필터를 따른다. 다른 GPU나 스위치를 합쳐 동일 장치 반복으로 단정하지 않는다. 등록 간격은 고장 주기 예측이 아니다.
- 부분 산출·근거 부족·서술 실패를 실행 성공과 구분한다. 기본 보고서나 검증된 일부 해석을 제공해도 원인 확정·업무 복구를 뜻하지 않는다.
- `rca-material/1`, `incident-first`, 과거 구조화 결과의 읽기 호환을 유지한다. 원문·근거 참조·추가 확인 사항을 보존하며 저장된 본문을 프런트엔드에서 새로 작성하지 않는다.

Fabric Manager 상태 코드에는 DCGM 정의(0 미지원·1 시작 전·2 시작 중·3 성공·4 실패·5 인식 불가·6 NVML 버전 낮음)를 표시한다. 0은 정상 상태가 아니라 해당 지표로 판단할 수 없다는 뜻이다. NVSwitch 보고서의 모델·드라이버는 이를 보고한 노드 GPU 라벨에서 가져온다. Pod 라벨을 제공할 수 없는 지표만 수집했다면 작업이 없다고 단정하지 않고 확인하지 못했다고 안내한다. AI 해석 실패는 HTTP 상태 외에 저장된 게이트웨이 오류 클래스와 출력 토큰/입력 길이 한도 종류를 함께 표시하며 민감한 오류 원문을 노출하지 않는다.

GPU별 요약은 같은 판독의 장치를 묶고 전송률 단위를 환산한다. 사건 전부터 0인 표본과 사건 뒤 급감을 구분하며, 단일 표본의 한계를 표시한다. 같은 Pod가 사용한 여러 GPU와 같은 노드의 다른 작업을 함께 보여주되 DCGM 라벨 관측을 할당 또는 실제 피해로 확정하지 않는다. AI 해석 실패는 HTTP 상태·사유와 코드 산출 결과를 분리하고 XID/SXID 요약이 없는 결과의 이유도 보존한다. 컴포넌트 알림은 저장된 Fleet 상태 보고(정상→오류 전환·사유별 보고)와 Worker가 저장한 `component_observations` 지표로 같은 여섯 구역을 채우며, GPU 전용 내용(공급사 체크리스트·리셋 방식 표)은 숨긴다. 행 재매핑 대기·실패, InfoROM 유효 같은 상태 코드는 조치가 필요한 값일 때만 리셋 필요·RMA 검토·InfoROM 무효로 표시한다. 이더넷 링크 상태가 끊김(0)이면 링크 끊김으로 표시한다. 누적 카운터는 사건 뒤 값과 늘어난 양(+N)을 함께 보이고, 나노초 제한 시간은 초·분·시간·일로 바꿔 보인다. 전용 Runbook 없이 일반 조사 Runbook만 선택된 컴포넌트 알림도 같은 여섯 구역을 쓰며, 그 지침(`general_fallback`)을 1·3장에 싣는다. 컴포넌트 알림의 1장은 Fleet 보고 사유를 한국어 사유명으로 보이고(이번 사유와 가능한 사유 전체), 대상은 컴포넌트별 설명으로 보인다. 사유·대상 표는 배포된 Fleet 원본의 사유 문구로 만든 `src/lib/componentReasons.ts`이고, 사유에 대응하는 판단 단계 항목은 맨 위로 올려 ▶로 표시한다. 2장은 접지 않고 모든 문장을 보이며, 맨 위에 단계 목차를 둔다. 대응 문장 안의 명령어, 작업에 영향이 큰 조치(재시작·재부팅·리셋·배출을 지시하는 문장), 금지·주의(하지 않습니다, 증거·데이터 손실)는 `src/lib/rcaHighlight.ts` 규칙으로 색을 달리한다. RCA 보고서의 명령어·장치 ID는 JetBrains Mono(`@fontsource-variable/jetbrains-mono`)로, 그 안의 한글은 본문 글꼴(Noto Sans KR)로 보인다. 글꼴 변수는 `.rca-operator-report` 안에서만 정해 운영 보고서에는 영향이 없다. 단순 언급이나 분석 단서("확정하지 않습니다")는 강조하지 않는다. Fleet 커널 이벤트가 있으면 그 기록 시각을 오류 발생 시각으로 쓴다. 보고서 머리에는 저장 구간의 마지막 오류 기록 시각을 표시한다. 알림 수신·해제 상태나 조회 종료 시점의 보고 여부로 현재 장애 지속·복구를 추정하지 않는다. XID 79는 사건 뒤에도 그 GPU 지표가 들어오는지를 3장 판정 첫 줄에 적는다.

판정과 시간 대조는 [rcaOperatorView](src/lib/rcaOperatorView.ts), 결과 표시는 [RcaNarrative](src/components/RcaNarrative.tsx)와 [RcaOperatorReport](src/components/RcaOperatorReport.tsx)가 소유한다.

## RCA 디버깅 화면

개발자·개발 콘솔의 `/jobs/:id`는 입력·출처 / 실행·시도 / 근거·데이터 / 결과·공개로 나뉜다. 시도 선택기는 모든 탭 상단에 있으며 탭·시도·선택 근거·복귀 필터를 URL에 보존한다. 워크플로우 팝업도 같은 시도와 근거를 공유한다. 없는 시도를 최신 시도나 0으로 대체하지 않는다. 공개 결과 참조는 시도 선택과 별개이며 실행 실패의 저장 사유는 한국어 설명과 원래 코드를 함께 제공한다.

입력은 고정 사건 revision·snapshot·outbox·즉시 보고서·정기 회차를 조회한다. 결과 발행 전에도 `/jobs/:id/trace`의 모델·실행 프로필·지식 버전을 확인하며 지식 후보 목록은 펼쳐 읽는다. 실행 당시 자료를 현재 사건 revision이나 현재 설정으로 대체하지 않는다. 현재 설정을 열면 조사 중인 작업의 시도·근거·목록 조건으로 돌아올 수 있다. 같은 작업의 선택 시도와 직전 기록을 단계·종료 사유·시각·원격 추론 상태로 비교하며, 다른 작업 비교는 접수 조건·버전·상태·공개 결과를 대조한다. 설정 식별자가 실제 모델 호출 성공을 증명하지는 않는다.

근거는 50건씩 조회하고 불러온 기록 안에서 검색·비교한다. 기록 생성 시각과 계획 순서로 정렬하며 생성 시각을 실행 시작이나 소요시간으로 추정하지 않는다. 원문을 열 때 ID/job/attempt, 지식의 ID/revision/hash를 검사한다. 연결 불일치나 API 오류는 본문 대신 별도로 표시한다.

워크플로우 디버깅은 저장된 수집·작성·자료 고정·보고서 호출과 원문 참조를 연결한다. 실제 요청·응답 횟수·usage·실패 경로만 표시하며 미기록을 0이나 성공으로 만들지 않는다. 과거 검토/목적/선택 기록은 당시 결과의 진단으로 유지한다.

Backend 요청 관찰은 현재 탭의 최근 50개 HTTP 메타데이터만 보여준다. 내부 Worker 호출·다운로드는 포함하지 않으며 페이지 재시작 때 초기화된다.

## Ops 보고서와 일정

`/reports/new`의 기본은 일간·주간 Namespace 활동·사건 비교 집계다. `?legacy=true`와 기존 종류 링크, 구 O계열 보고서·월간 일정·시간대를 보존한다. `quality.report_format=report-aggregate-v1`은 [AggregateReport](src/components/AggregateReport.tsx)를 사용한다.

기존 보고서 목록·상세는 RCA와 같은 표·카드·제목 체계를 유지한다. 요청 정보·목차·근거 대화상자, 시간대 crosshair와 모든 선택 계열의 tooltip, 그래프별 Namespace 선택, 보조 작업 관측 1.4절을 보존한다. 운영 콘솔도 같은 AggregateReport를 재사용하며 두 본문 스타일을 합쳐 적용한다.

Namespace 주제의 `quality.observation_diagnostics`가 있으면 활동률 산출·기간 비교의 제한을 AI 서술과 별도로 표시한다. 저장된 원인을 먼저 보여주고 대상·현재/이전 기간별 제외 시간을 펼쳐 확인한다. 검증 미실행을 신원 충돌로 표시하지 않으며, 진단이 없는 과거 결과의 예산 소진 여부를 추정하지 않는다. 동일 설명은 Worker의 `limitations`에 저장되어 기존 HTML 다운로드 경로에서도 보존된다. 진단 의미·집계 단위는 [Ops 명세](../docs/specs/ops-agent/aggregate-report-v1.md)를 따른다.

표·그래프는 저장된 계산값과 단위·분모·제외 이유를 따른다. GPU–Pod 연결 활동은 독점 할당량이 아니며, 결측 구간은 0으로 잇지 않는다. 활동률·메모리·작업 대기 관측과 완료 Job 표본을 구분한다. 대기 Pod 최댓값은 대기 시간이 아니고 완료 Job 경과시간은 순수 GPU 실행시간이 아니다. 클러스터별 그래프 범례·Namespace 선택은 독립적이다.

AI 해석, AI가 선택한 기존 변화, 계산 요약, 출처 미기록 문장을 구분한다. 저장된 요약 분리 정보가 원문과 일치할 때만 결정·근거를 나눠 보여준다. 조건부 제안과 과거 저활동 구간은 향후 가용 GPU나 이동 대상의 확정 정보가 아니다. 선별 기준·근거·제한은 펼쳐 확인한다. Namespace 운영 제안은 선별된 항목만 클러스터별 카드 안에서 클러스터→Namespace 이름순으로 묶고, 같은 Namespace 안에서는 저장된 제안 순서를 유지한다. 카드 제목에 클러스터를 명시하고 내부 Namespace 라벨·콜론·값의 열을 맞추며, 유형별 소제목과 관측·비교 시간을 표시한다. 같은 대상의 떨어진 항목은 합쳐 보이지만 재선별하거나 수치를 합산하지 않는다. 산식과 생산자 의미는 [Ops 집계 명세](../docs/specs/ops-agent/aggregate-report-v1.md)가 소유한다.

일정의 활성화·접수·실행·발행은 별도 상태다. 예정 회차, 실제 작업, 다음 예정 시각을 연결하고 일시중지가 이미 실행 중인 작업을 취소하는 것처럼 표시하지 않는다. 보고서 생성과 반복 일정 생성은 별도 제목·복귀 경로를 사용한다.

신규·운영 콘솔의 **현재 화면 HTML 저장**은 렌더링된 범위·기간·제한을 저장한다. 전체 원본 내보내기가 아니며 폼·버튼·링크를 제거하고 CSP를 포함한다. 서버 HTML 다운로드도 같은 대상 묶음·소제목·시간 구분을 적용하고 CSV는 보존한다. 출력과 화면 조회는 LLM을 다시 호출하지 않는다.
