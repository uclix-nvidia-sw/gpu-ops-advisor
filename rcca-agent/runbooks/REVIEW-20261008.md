### PCIe·NVLink 보조 조회 연결

XID 32·79에 D44 PCIe replay 원본을, XID 74에 D33/D34 NVLink 수신·송신량을 선택 가능한 보조 조회로 추가했다. 원본 누적 replay의 절대값은 사건 증가량이 아니며 이 변경은 reset-aware 계산을 추가하지 않는다. NVLink 트래픽은 연결 상대·source port·partition 토폴로지를 입증하지 않는다. 해당 장치·시간의 추가 근거가 없으면 원인·영향 범위는 미확정으로 유지한다.

다섯 원본(XID 54·163·32·79·74)에 대해 정상 표본/빈 응답/조회 실패의 15개 Worker fixture 사례를 검사했다. D33/D34/D44는 v7 테스트 프로필에 명시적 fixture 정의를 등록했으며, 실제 공통 프로필의 binding·단위·cluster 파라미터·candidate 차단은 별도 검사했다. 이 검사는 운영 MCP의 대상 라벨 발견이나 실제 토폴로지를 검증한 것이 아니다.

### D07 삭제 여부

현재 Ops의 O07은 D07과 D12를 계획하고 D07에서 UID, 미배치(node 없음), 비종료(terminal=false), effective-v1 의미를 확인하여 자원별 요청량을 합산한다. 따라서 JSON의 D07만 삭제하지 않는다. 미검증 binding은 계속 실행되지 않는다.

`gpu_ops_effective_unbound_request`라는 메트릭 이름은 영구 요구사항이 아니다. scheduler 원본과 KSM 신원·상태를 기존 수집 경로로 받아 UID/시간/미배치를 코드로 검증하는 전환은 별도 구현·검증 대상이다. 이 작업에서는 D07 설정과 Ops 계산을 변경하지 않았다. O07 자체를 폐기할 경우에는 계획·계산·표시·회귀검사까지 함께 변경해야 한다.

### 현재 공통 설정과 Worker 연결 회귀

앞선 v7 기반 fixture 검사에 더해 저장소 `agents/config.example.json`을 수정 없이 읽는 15개 Worker 사례를 추가했다. 실제 Runbook 원본과 모의 MCP datasource 발견을 함께 사용하며, D04/D11/D33/D44 조회가 요청 cluster_id·GPU UUID·node 조건을 포함하고 binding ID를 기록하는지 확인했다. D34는 현재-profile binding·수집 차단 검사에 포함하지만 Worker의 제한된 추적 단계에서 실행되었다고 주장하지 않는다.

다섯 보조 D 각각에 대해 GPU 대상 라벨 매핑을 제거하면 설정 검증에서 거부되고, 동일 클러스터를 가진 datasource가 둘이면 실제 메트릭 조회 전에 차단되는 10개 사례를 추가했다. 이는 잘못된 설정/모호한 경로에 대한 로컬 검사이며 운영 데이터의 GPU·노드 관계를 확인한 것은 아니다. 관련 binding/두 소비자 회귀를 포함해 238개 검사를 통과했다. 새 runtime 동작 변경 없이 기존 차단 경계를 확인했다.

## 최종 보고서와 회귀검사

현재 최종 편집 LLM은 주어진 문장 ID를 정렬한다. 자유 서술을 채택하는 인터페이스가 아니다. 원인 후보는 별도 synthesis 결과에서 이미 보고서 문장으로 들어간다. 유효하지 않은 ID·빈 ID·자유 서술 응답을 거부해도 원인 후보, 근거 참조, 부족한 입력과 분석 완료 상태는 보존하는 회귀검사를 추가했다.

새 fallback 진단은 설정 없음·응답 거부·예외를 구분한다. 과거 실행의 원인을 소급 확정하지 않는다. 전송 중 원격 실행 불확실성과 취소는 기존 fencing 경로로 전파한다.

DB 보류 해제 후에는 최신 코드/DB 상태 재확인 → 검토된 내용의 새 draft revision → 해시·적용 조건 검토 → 발행 → 새 RCA의 고정 revision·실제 근거·최종 결과 확인 순서다.

## PR와 운영 발행의 완료 조건

코드 PR은 계약 실패 상세 진단, 오프라인 감사, 오류별 조사 계획과 최종 편집 fallback 진단을 범위로 한다. Fleet 상태 fact 활성화, 전체 카탈로그 승인 및 운영 RCA 완료를 포함하지 않는다.

- 일반 회귀와 형식/링크 검사 후 격리 DB의 Backend–JC–Worker 통합 검사를 완료해야 PR 준비 완료로 보고한다. 운영 슬롯 테스트를 대신 사용하지 않는다.
- 현재 Fleet 시각 조건은 `normalized_health`뿐 아니라 `error_code`, `producer_contract`, `component`, `severity`의 fact 승격에도 적용된다. 감사의 `fleet_time_gated_facts`는 요구된 항목 중 이 조건이 걸린 목록이다. 원본 관측만 요구하는 경우와 구분한다.
- 새 초안은 compatibility 미설정이며 자동 승인하지 않는다. 배포된 생산자/대상/시각 의미와 오류별 필수 근거 검수가 끝난 항목만 이후 검토·발행한다.
- PR 생성, merge, 배포 및 운영 재실행은 서로 다른 단계다. 운영 재실행 시점은 진행 중인 슬롯 동시성 시험과 조율한다.
