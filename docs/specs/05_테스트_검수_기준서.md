## RCA 접근·Ops 최종 보고서 회귀 — 2026-09-30

RCA 첫 화면의 보고서 탭/바로가기, 공개 참조가 없는 작업의 링크 미노출, Ops 다섯 섹션과 기존 narrative 호환을 확인한다. 수치 없음/실제 0, LLM 성공/무효 응답/미설정/HTTP 실패에서 수치·품질·부족 사유 보존을 검증한다. 실제 Worker→JC 공개→화면/HTML 소비, Worker artifact checksum/HTML escape 및 CSV 원시 값 유지가 필요하다. fixture 검수와 운영 모델/관측 품질은 구분한다.

## Fleet RCA 회귀 기준 (2026-09-30)

0.505ms 경계 축소와 31개 Fleet 로그를 재현해 원본 기간 partial 유지, 실제 구간 관측 생성, 원인 Synthesis 입력 참조, degraded 후속 D02, R02 D08/D06 계획을 확인한다. 불명 target/동일 노드만으로 직접 GPU–Pod 관계를 만들지 않는다. 다른 partial·미등록 상태·잘못된 시각/식별/코드는 안전하게 제외하거나 unknown으로 남긴다. 새 target 투영 후 동일 생명주기 재접수에 incident/outbox/snapshot이 증가하지 않는 DB 검사를 포함한다. 실제 producer 시각 의미·운영 LLM 품질은 fixture 통과와 별도로 검수한다.

## 2026-09-30 RCA 최종 보고서 추가 검수

T33~T35의 원인 분석 생략과 최종 설명 편집을 구분한다. 유효 실행의 fast path, 승인 Runbook 없음, 관측 근거 없음, 조회 실패, LLM 미설정/무효 출력/확정된 HTTP 실패에서도 다섯 섹션의 비어 있지 않은 보고서가 있어야 한다. 모델 구성·예산이 허용되면 관측 유무와 무관하게 최종 편집 호출을 시도한다.

- 입력 alert·원천 조치는 미검증/미수행, supported 원인은 확정 아님으로 표시한다. 모델이 없는 ID를 선택하면 기본 보고서로 대체하고, 선택에서 빠진 부족 근거·실행 조건도 남긴다.
- 보고서 작성 후 result_status·assessment·인과 수준·권고 자격과 snapshot/hash가 바뀌지 않아야 한다. 원격 종료 불명은 T39의 실패·격리를 유지한다.
- 실제 격리 DB/JC/Worker에서 근거 없는 실행의 보고서 저장·공개를 검사한다. 모델/Grafana fixture 시험은 운영 품질 검수가 아니다.
- Frontend는 공개 결과에만 다섯 섹션과 기본 보고서 여부를 표시하고 HTML을 escape한다. 구버전 narrative 없는 결과도 표시 가능해야 한다.

버전 1.3 · 시험 기준과 현재 회귀 테스트의 연결을 관리한다. 실행일·환경·범위는 모듈별 QA를 따르며, 실행 증거가 없는 제품 시험은 NOT RUN으로 유지한다. 구버전 데모 검수 PASS를 승계하지 않는다.

## 시험 환경·증거

Backend·Incident·JC·RCA·보고서를 각각 다른 프로세스로 실행한다. 테스트 PostgreSQL과 stub 관측/추론을 사용한 계약 시험 후 실제 CPC별 통합 시험을 수행한다. 자원 한도·시각·입력 snapshot·버전·request/job/attempt ID·기대/실제 값을 함께 저장한다. 실환경에 부하/장애를 주는 시험은 시험 환경과 범위를 따로 정한다.

기본 고정 프로필: 종류별 Worker 각 1개, worker_slots=1, kind_limit 각각 1, shared_limit=1, max_attempts=3, lease=30초, heartbeat=5초. 이는 검수용이며 운영 권장값/확정값이 아니다. test clock으로 마감·lease·달력 경계를 제어한다.

## 합격·기록

필수 시나리오 실패·중복 final·용량 초과·데이터 유실은 불합격이다. 환경 입력 부재는 BLOCKED와 필요한 입력을 기록하며 PASS로 바꾸지 않는다. 문서 검사 통과는 위 시험 PASS가 아니다.

실행 기록 필드: test_id, build/contract/config revision, environment, input_ref, expected, actual, evidence_ref, executed_at, executor, status=NOT_RUN/PASS/FAIL/BLOCKED, defect_ref. 각 고정 사례와 R/O 변형을 독립 기록한다.
