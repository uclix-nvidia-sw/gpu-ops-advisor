# Fleet / GPUd component·오류 카탈로그

상태: 런북 작성용 정적 소스 참고자료 — 분석 기준 commit의 정의이며 현재 배포 상태나 실행 가능한 runbook을 뜻하지 않음

> **component는 특정 항목을 점검하는 담당 모듈입니다. XID와 SXID는 여러 담당 모듈이 다루는 오류 중 일부입니다.**
>
> 이 문서는 **component 목록 + XID·SXID 전체 정적 정의 + 다른 component의 주요 조건 요약과 코드 위치**를 담습니다. 모든 component의 모든 오류 조건을 빠짐없이 풀어 쓴 카탈로그는 아닙니다.

## 1. component란?

서버를 점검하는 팀에 GPU 담당, 디스크 담당, 네트워크 담당이 나뉘어 있다고 생각하면 쉽습니다. 이 각각의 **점검 담당 프로그램**이 component입니다.

| 용어 | 쉬운 의미 | 예시 |
|---|---|---|
| component | 누가, 어떤 영역을 점검했나? | `accelerator-nvidia-error-xid` |
| 오류 코드 / 조건 | 무슨 문제가 발견됐나? | XID `79`, 파일시스템 읽기 전용 전환 |
| event_type | 발생 이벤트를 어떤 종류로 분류했나? | `Warning`, `Fatal` |
| health | 현재 담당 영역의 상태는 어떤가? | `Healthy`, `Degraded`, `Unhealthy` |
| suggested_actions | 어떤 조치를 권고하나? | 설명 + `repair_actions` 배열 |

다음은 개념을 설명하기 위한 예시입니다. 실제 전송 JSON의 전체 스키마를 그대로 나타낸 것은 아닙니다.

```text
component: accelerator-nvidia-error-xid
XID 번호: 79
health: Unhealthy
```

“**GPU XID 담당 모듈**이 **79번 오류**를 확인했고, 현재 상태를 **비정상**으로 판단했다”라고 읽으면 됩니다. component 이름 자체가 오류 번호나 Unhealthy를 뜻하지는 않습니다. 같은 component에서 정상 상태도 나올 수 있습니다.

## 2. 오류는 XID와 SXID만 있나?

**아닙니다.** XID·SXID는 번호를 가진 오류 체계이고, 다른 component는 측정값·상태·이벤트·임계값 등으로 문제를 판단합니다.

| component 예시 | 담당 영역 | 오류를 구분하는 방법 |
|---|---|---|
| `accelerator-nvidia-error-xid` | NVIDIA GPU XID 오류 | XID 번호; 일부는 NVLink 상세 정보까지 사용 |
| `accelerator-nvidia-error-sxid` | NVSwitch SXID 오류 | SXID 번호 |
| `accelerator-nvidia-infiniband` | InfiniBand 포트 | 포트 상태, DOWN 지속, flapping 등 |
| `disk` | 디스크·NVMe·파일시스템 | I/O 실패, 읽기 전용 전환 등 오류 조건 |
| `os` | 운영체제 상태 | 파일 디스크립터 사용량 등 조건; GPUd에는 D-state 평가도 있음 |
| `accelerator-nvidia-dcgm-thermal` | DCGM 온도 관련 감시 | DCGM 필드·건강 상태 결과 |

따라서 “에러 카탈로그”를 만들 때는 **오류 번호가 없는 조건 기반 오류도 별도로 포함**해야 합니다.

```text
component: 어떤 영역의 담당 모듈인가?
    └─ 오류 코드 또는 발생 조건: 무슨 문제인가?
           ├─ 이벤트 종류 / 현재 health
           └─ 기본 권고 → 이력·임계값 반영 → 현재 권고
```

## 3. 이 문서에 포함된 범위

| 구분 | 수록 내용 | 범위와 한계 |
|---|---|---|
| Fleet component 목록 | SDK에 정의된 27개와 Fleet registry 등록 여부 | 실제 Fleet registry 등록은 23개. 소스 존재와 실제 활성화는 다름 |
| GPUd component 목록 | 소스에 정의된 32개 | 실제 활성화 여부는 실행 설정에 따름 |
| XID 상세 표 | **저장소별 172개**의 설명·event_type·기본 action | 분석 커밋의 정적 details 맵. NVLink 상세 처리와 상태 평가 전 기본값 |
| SXID 상세 표 | **저장소별 92개**의 설명·event_type·기본 action | 분석 커밋의 정적 details 맵. 상태 평가 전 기본값 |
| 다른 component | 아래 주요 조건 요약 및 마지막 action 할당 코드 인덱스 | **모든 오류 분기의 완전한 상세 표는 아님** |
| NVLink 세부 규칙 | JSON 파일에 저장소별 raw rule 94개 | 최종 action은 매칭·override 코드까지 함께 확인해야 함 |

**172개·92개는 저장소별 수치**입니다. 두 저장소에서 같은 오류 정의가 중복될 수 있으므로 서로 다른 오류 528종이라는 의미가 아닙니다.

분석 기준 커밋:

- Fleet: `84f99beef3e633071ad0998b10629b01fb294eaf`
- GPUd: `9606bb8f6813fdd944cc9a349566e35075917805`

Fleet은 저장소 내부 SDK를 사용합니다. GPUd의 현재 동작을 그대로 Fleet의 동작으로 간주하면 안 됩니다.

## 4. repair_actions 표를 읽는 법

`repair_actions`는 `suggested_actions` 안에 들어 있는 **조치 종류 목록**입니다. 서로 독립적인 두 카탈로그가 아닙니다.

```json
{
  "suggested_actions": {
    "description": "조치 설명",
    "repair_actions": ["REBOOT_SYSTEM"]
  }
}
```

| 표에 나오는 값 | 의미 |
|---|---|
| `REBOOT_SYSTEM` | 시스템 재부팅 권고 |
| `HARDWARE_INSPECTION` | 하드웨어 점검 및 필요한 수리 권고 |
| `CHECK_USER_APP_AND_GPU` | 사용자 앱과 GPU 진단 권고 |
| `IGNORE_NO_ACTION_REQUIRED` | 명시적으로 조치 불필요 |
| `nil (미정의)` | 해당 정적 항목에 권고가 정의되지 않음. 정상·무해 또는 명시적 IGNORE라는 뜻은 아님 |

**기본 권고와 현재 권고는 구분해야 합니다.** 예를 들어 XID 79의 정적 표에는 `REBOOT_SYSTEM, HARDWARE_INSPECTION`이 있지만, 상태 평가에서는 첫 action만 유지하거나 재부팅 이력에 따라 하드웨어 점검으로 바뀔 수 있습니다. 표에 있는 모든 action을 즉시 실행하라는 뜻이 아닙니다.

같은 component여도 오류 코드·발생 조건·NVLink 상세 값·재부팅 이력·설정 임계값에 따라 권고가 달라집니다. `event_type`과 현재 `health`도 서로 다른 필드입니다.

## 5. XID·SXID 외 주요 조건 기반 오류

다음은 소스에서 확인한 주요 예시입니다. 전체 오류 분기를 망라한 목록은 아니며, 실제 조건과 코드 위치는 문서 마지막 인덱스를 함께 확인해야 합니다.

| 적용 저장소 | component | 문제 또는 조건 | 권고 방식 |
|---|---|---|---|
| Fleet | `accelerator-nvidia-persistence-mode` | GPU lost / reset-required | `REBOOT_SYSTEM`; persistence mode OFF와 동일 조건은 아님 |
| Fleet | `accelerator-nvidia-infiniband` | 장시간 DOWN·flapping 판단 조건 충족 | `HARDWARE_INSPECTION`; 모든 포트 이상에 무조건 적용하는 것은 아님 |
| Fleet / GPUd | `disk` | RAID 실패, 읽기 전용 파일시스템, NVMe path 실패·timeout·device disabled, 범위 초과 접근, buffer I/O·superblock 쓰기 오류 | 오류·재부팅 이력 평가로 재부팅 / 하드웨어 점검 / 권고 없음 결정 |
| Fleet / GPUd | `os` | 파일 디스크립터 관련 임계값 조건 | `CHECK_USER_APP_AND_GPU` |
| GPUd | `accelerator-nvidia-remapped-rows` | row remapping pending / failed | pending: 재부팅, failed: 하드웨어 점검 |
| GPUd | `accelerator-nvidia-hw-slowdown` | 감속 이벤트 빈도 임계값 초과 | `HARDWARE_INSPECTION` |
| GPUd | `accelerator-nvidia-gpu-counts` | 기대 GPU 수 불일치 | 오류·재부팅 이력 평가 |
| GPUd | `accelerator-nvidia-nvlink` | inactive link 및 특정 peer probe 실패 조건 | `REBOOT_SYSTEM` |
| GPUd | `nfs` | hang 이벤트 | 오류·재부팅 이력 평가 |
| GPUd | `os` | 지속 D-state 프로세스 | 이름 조건과 재부팅 이력에 따라 재부팅 / 하드웨어 점검. 이름 조건 불일치 시 Degraded, 조치 권고 없음 |
| Fleet | `accelerator-nvidia-dcgm-*` | 각 DCGM 건강 상태·필드 오류 | 이 커밋의 component 코드에서 SuggestedActions 직접 할당은 확인되지 않음. health/reason/incidents 확인 필요 |

권고가 없는 component도 오류나 Unhealthy를 보고할 수 있습니다. **“action 없음 = 오류 없음”으로 해석하지 마세요.**

- component 목록: 담당 모듈 이름과 소스 위치 확인
- Fleet XID / SXID: Fleet 내부 SDK의 코드별 기본 정의 확인
- GPUd XID / SXID: GPUd의 코드별 기본 정의 확인
- NVLink 규칙 안내: 상세 조건을 담은 JSON과 최종 매칭 코드의 관계 확인
- action 할당 코드 인덱스: 조건 기반 권고를 설정하는 코드 위치 확인
