# 07. 프론트엔드 개발 명세서

## 범위와 구현 상태

이 문서는 네 탭 GUI 개편의 구현 계획과 기존 호환 조건을 관리한다. **기존·운영·개발자 화면을 보존하고 신규 탭을 별도 구성으로 구현했다. 운영 배포와 전체 검수 완료를 의미하지 않으며, 검증 범위는 QA를 따른다.** 목표 화면·필드·행동은 [08](08_GUI_화면설계서.md), API 계약은 [02](../backend/02_백엔드_API_작업명세서.md), 검수는 [05](../05_테스트_검수_기준서.md#네-탭-gui-개편-검수), 실행 증거는 [Frontend QA](../../../frontend/QA.md)가 소유한다.

사용자 요구는 `기존 / 운영 / 개발자 / 신규` 네 탭, 신규의 결과 중심 구성과 raw/개발 정보 제거, 개발용 유지다. 이 계획은 신규 메뉴를 운영 현황·장애 분석·운영 보고서로 정리하고 사건 중심 탐색을 채택한다. 인증/RBAC, 새 분석 엔진·큐·스케줄러, 수동 RCA, 장비 자동 조치, 개발용 삭제는 범위 밖이다.

## 정보 구조와 코드 경계

08의 메뉴·경로표가 화면의 단일 기준이다. 기존 경로와 classic/operations/developer 저장값·기본 classic을 유지하고 `new`를 신규 탭으로 추가한다. 버튼은 기존 / 운영 / 개발자 / 신규 순서다. 신규는 명시적으로 선택한 경우에만 적용하며 기존 선택값을 이행·덮어쓰지 않는다. 저장 키 `gpu-advisor-view`를 재사용한다.

Shell/라우팅에서 신규 전용·개발용 전용·공통 결과의 경계를 먼저 정한다. 신규의 개발 경로 직접 진입은 안내/명시적 전환으로 처리하고 개발 화면을 먼저 마운트하지 않는다. UI 모드로 API 접근 권한이 생기거나 차단됐다고 설명하지 않는다.

결과와 계산 로직을 복제하지 않는다. RcaNarrative·RcaGuidance의 운영 설명, ReportStatements·BasicReport·AggregateReport와 그래프를 재사용한다. 구조화된 관측은 오류 이벤트와 상태 보고의 의미·시각·제한만 선택해 표시한다. 원본을 요구하는 콜백·EvidenceDialog·RcaEvidence·RcaEvaluationTrace는 개발용 구성에서만 연결한다. RcaResult의 기존 `showEvidence=false`만으로는 나머지 진단/원본이 사라지지 않으므로 신규 모드의 완결된 분리로 간주하지 않는다.

조회 hook·명령·한국어 상태 사전은 기존 구현을 재사용한다. 화면별로 새로운 API client·전역 상태 프레임워크·계산 엔진·CSS 시스템을 만들지 않는다. 공통 변경은 개발용 소비자까지 검사한다. 신규 전용 스타일은 범위를 제한하고 기존 디버깅 모달·표 스타일을 변경하지 않는다.

## API 의존성과 선행 작업

| 기능 | 현재 사용 가능한 API | 필요한 작업/제한 |
|---|---|---|
| 사건 목록 | `GET /incidents`: scope, status, from/to, cursor. status는 사건 state 우선, 기간은 발생 시각 | 같은 페이지에 최신 실행/공개 결과 요약 제공. 검색·검토 필터는 이번 기본 범위에서 제외 |
| 사건 최신 결과 | 상세 analyses는 기존 job_id/status 연결을 보존 | 목록·상세의 rca_summary를 소비. 기존 analyses 유지. 상세의 각 job을 전부 조회하지 않음 |
| 이전 분석 | `GET /analyses?incident_id=...`, cursor/limit; 각 항목의 result_ref와 품질 | 펼칠 때 조회. 조회한 첫 페이지에 공개 결과가 없다고 전체 미발행으로 단정하지 않음 |
| 특정 분석본 | `GET /analyses/:id` | 기존 공개 결과만 소비. 사건 연결·저장 대상·시각을 유지 |
| 현황 | `GET /dashboard`, `/incidents`, `/reports` | 현행 제공 숫자와 최근 목록만 사용. 새 KPI API를 추가하지 않음 |
| 보고서·일정 | 기존 `/reports`, `/schedules`, occurrences, export | 생성/조회/명령 계약 재사용. 신규·구형 일정 편집 선택지 분기 |
| 검토·조치 | `/reviews`, 사건 PATCH, 기존 대상/근거 조회 | UI 입력 변환과 subject 보존. 서버 검증·If-Match·멱등키 유지 |
| HTML 출력 | 신규의 현재 화면 HTML 저장 | 기존 결과 컴포넌트가 렌더링한 본문·범위·기간·제한을 저장한다. 숨은 원본 데이터를 별도 렌더링하지 않는다. 선택된 그래프/화면 범위임을 파일에 표시하고 스크립트·폼·링크를 제거하며 CSP를 포함한다. 기존 세 모드의 서버 HTML/CSV는 유지 |

Backend 보완의 선택 필드·정렬·null·공개 연결 조건은 [02 GUI 조회 계약](../backend/02_백엔드_API_작업명세서.md#gui-개편용-사건-분석-요약)에 정의한다. 이 로컬 변경의 목록·상세 응답에 구현했다. 구 서버의 필드 부재는 미지원으로 구분한다. DB schema·Worker 실행·결과 생성은 바꾸지 않는 읽기 투영 작업이다. Backend를 먼저 적용할 수 있도록 additive DTO로 개발하며 구 Frontend의 소비를 보존한다.

구 Backend와 연결한 새 신규 UI에서는 summary 부재를 `분석 상태 미확인`으로 표시하고 사건 본문은 읽을 수 있게 한다. 최신 결과 선정은 요약 계약이 제공된 뒤 활성화한다. 이 호환 상태를 개편 완료로 선언하지 않는다. UI에서 사건마다 detail을 호출하는 N+1이나 `/analyses` 첫 페이지를 임의 합치는 우회는 금지한다.

## 보존할 동작과 호환 계약

- Backend `/api/v1`만 호출한다. RCA는 Incident에서 접수하고 JC가 공개를 확정한다. 신규 화면에서 새 RCA 작업·재분석·장비 제어를 만들지 않는다.
- 공개 `result_ref`와 실행 상태·자료 품질·설명 상태를 분리한다. 공개 전 candidate, 성공처럼 보이는 임시 결과, 프론트가 만든 원인·해석·절감 수치를 표시하지 않는다.
- scope·기간·ID·revision이 바뀌면 캐시/응답이 섞이지 않게 한다. 상세의 저장 범위, 보고서 생성 당시의 시각과 알림 상태를 현재 선택값으로 바꾸지 않는다.
- 새 보고서는 집계 주제·일간/주간을 사용한다. legacy/kind의 O01~O11 폼, 저장된 주제별 집계·비교/조치/자원 조건·기존 월간 일정은 개발용 호환 경로와 결과 읽기에서 유지한다. 구 요청을 집계 계약으로 자동 변환하지 않는다.
- 접수·명령의 멱등 키, If-Match, 서버 can_cancel/can_retry/can_delete, 409 재조회, 검토·조치 불변 기록과 정정 연결을 유지한다. 정정 UI는 기존 evidence_refs를 조용히 삭제하지 않는다.
- 일 단위 입력·KST·완료 기간·기존 시간대/DST 및 occurrence/revision 의미를 유지한다. pending은 일정 전달, queued는 job 실행 대기이며 서로 바꾸지 않는다.
- 신규 HTML은 현재 화면의 공개 결과 출력이며 기존 세 모드의 서버 HTML/CSV 출력은 유지한다. 다운로드 오류를 성공처럼 표시하지 않으며 내용 재생성을 위해 LLM을 호출하지 않는다.
- 클러스터 등록, 모델·라우팅, Runbook 초안/검토/발행, Worker·용량 상태는 개발용에 유지한다. 발행 revision 직접 수정·GUI 용량 변경은 추가하지 않는다.
- 개발용 보고서 수집 진단은 계획 중단·전체/일부 응답·query/CPC/비교 기간·누락/실패 사유·원본 연결을 유지한다. 조회 응답 시간은 GPU 사용시간이나 표본 커버리지가 아니며 미기록을 미조회로 단정하지 않는다. 같은 조회의 재사용 근거를 중복 집계하지 않고 표본 합계를 고유 표본 수로 바꾸지 않는다.
- 구 O계열 호환 폼은 O10의 조치 ID·비교 기간(직접 요청만), O07 자원 조건, 종류 변경 시 부속 입력 초기화, 지원 group_by·topic_group_by 검증을 유지한다. 구 criteria의 수치를 신규 기준으로 소급 계산하지 않는다. 보류 권고의 사유·전제·다음 확인과 미수행 상태도 읽기 호환한다.
- queued/running/retry_wait 조회·오류 backoff와 Retry-After, terminal 처리, 공개 hash 앵커의 로드 후 이동을 유지한다. 신규 HTTP의 UUID·SHA-256은 기존 browserCrypto를 사용한다. React 문자열 escape·문단 보존·서버 출력의 escape/CSP를 유지한다.
- 개발용 클러스터 등록은 기존 실제 라벨 ID·멱등 POST·입력/중복 오류를 유지하며 등록 성공을 수집 성공으로 표시하지 않는다. scope가 없어도 연결·설정에 접근할 수 있어야 한다.
- 보고서 삭제는 현재 종료 상태·참조 보호·사유·버전 검사를 유지한다. 삭제 완료 전 목록에서 먼저 지워 성공처럼 보이지 않게 한다. RCA 원본과 다른 기록을 삭제하지 않는다.

## RCA 평가 분리 표시

이 절은 기존 평가·디버깅 소비 계약이다. 개편 신규 화면에는 08의 결론·근거·한계만 표시하고, 아래 단계·예산·원본·revision 진단은 개발용에 유지한다.

신규 combined 기록은 **작성 LLM / 별도 검토 LLM** 역할로 표시하며 구 기록의 LLM ①②③ 표시는 유지한다. 두 분석 호출을 전체 workflow 호출 수와 혼동하지 않는다. 최종 순서는 다음 행동 결정 → 보고서용 RCA 근거 자료 고정 → 최종 보고서 작성 → 기존 작업의 저장·공개 상태다. 자료 고정은 원인 확정이 아니다.

Runbook 목표 카드에서 질문·결론 범위, 필수 여부, 코드/LLM 담당, 충족/불충족/미확인, 원본 refs, 차단 조건, 남겨도 되는 미확인과 revision/hash를 읽는다. `goal_achieved/goal_not_met`, `same_evidence_rewrite_blocked/no_new_evidence`, 해석만 보존·원인 미채택을 구분한다. 다른 초안의 검토나 실패한 검토를 목적 달성 배지로 사용하지 않는다. 원문/관련 기록 버튼은 기존 범위 검사를 유지한다.

상세 실패 코드는 신규 `failed` 상태에 가려지지 않으며 결과 요약과 팝업에서 같은 사유를 설명한다. 호출 전 생략은 명시적 0회/사전 검사 기록으로, 전송·응답은 저장된 횟수로 표시하고 미기록을 0회로 만들지 않는다. 최종 초안 미검토와 출력 잘림·실제 호출 기록을 구분한다. `quality.analysis.error_events`만 있는 결과도 관측 근거를 표시하며 이벤트 시각과 상태 보고/Loki 시각, 보고된 재고 일치와 독립적인 신원 확인을 나눈다. 연결 후보 UUID·보고된 PCI·재고 목록·근거 ID는 저장값만 보여주고 UI에서 장치를 다시 매칭하지 않는다. 알 수 없는 관계·제한 값은 원문을 유지한다.

기본 접근 경로는 **개발측 → 사건·RCA → RCA 조사 결과 → 상단 ‘워크플로우 디버깅’**(`/analyses/:id`)이다. 개발측 RCA 작업 상세(`/jobs/:id`) 상단에도 같은 버튼을 제공한다. 버튼은 같은 화면에 모달을 열며 시도 선택, 저장 기록 목록, 이전/다음 기록 이동을 제공한다. 각 기록에서 무엇을 했는지, 저장된 이유·선택 조건, 처리 방식, 입력·결과·근거 ID를 확인한다. 조회 목적은 같은 작업·시도의 저장된 조사 계획과 연결한다. 고정된 단계 역할 설명과 개별 실행 이유를 분리하며 미기록 사유를 추측하지 않는다.

기존 **작업 디버깅 → RCA 작업 → 근거·데이터**(`/jobs/:id?tab=evidence`)의 ‘평가 실행 흐름’도 유지한다. ‘요청 크기·예산 사전 검사’에서 요청별 크기/상한, 남은·예약·사용 가능 예산, 보수적 필요량, 최초 출력 상한 계산값과 호출 여부를 확인한다. 모달은 기존 작업별 근거 API를 50건씩 읽으며 추가 페이지·조회 실패·빈 기록을 구분한다. 근거 상세의 ID/job/attempt가 다르면 본문 표시를 차단한다. 근거 참조는 같은 작업·시도 범위에서만 이동한다. 신규/운영측 결과에는 디버깅 버튼을 추가하지 않는다.

입력 상한 초과와 토큰 부족은 서로 다른 한국어 사유로 표시하며 동시 발생 시 두 조건을 모두 보여준다. 변경 초안의 재검토 실패 상세도 숨기지 않는다. 모델 보고 usage와 미보고 응답의 보수적 차감량을 구분하고, 기록이 없는 과거 요청을 0회·상한 이내로 추정하지 않는다. 새 진단은 갱신된 Worker의 신규 실행에서 생성되며 Frontend 배포만으로 과거 결과를 채우지 않는다.

[11의 설계·개발](../rca-agent/11_RCA_Agent_모듈_설계서.md#평가-분리-설계개발)을 구현한 표시 계약이다. 배포 여부와 실제 브라우저 확인 범위는 Agent QA를 따른다. 필드·enum은 [04 §8.1](../common/04_Agent_동작_판단_명세서.md#81-rca-평가-분리-결과-확장)을 사용하며 화면에서 별도 품질 점수나 상태 판정을 만들지 않는다. 기존 S07 RCA·최종 보고서·작업 디버깅 화면을 확장하고 새 접수/재분석 화면은 만들지 않는다.

| 사용자 표시 | 표시할 내용과 주의점 |
|---|---|
| 수집 상태 | complete=수집 완료, partial=부분 수집, failed=수집 실패, not_requested=수집 생략과 이유. 빈 결과를 장애 없음으로 표시하지 않음 |
| 증거 상태 | 해석 기록의 확인 내용·추론·미확인·상충. execution complete를 ‘모든 증거 확인’으로 표현하지 않음 |
| 분석 품질 | acceptable=근거 범위에서 타당, revision_required=수정 필요, undetermined=판단 불가. failed/skipped는 미검토와 이유 |
| 원인 수준 | 기존 causal_status·confirmation rule 그대로 표시. 검토 통과로 확정 배지 부여 금지 |
| 조사 상태·종료 이유 | attempt의 조사 종료와 이유. Incident 종결·장비 회복·JC 성공과 구분 |
| LLM 수행 | 해석·분석·검토·수정·선택·편집 단계의 완료/실패/생략과 사유 |

결과 요약의 ‘결과 품질’이라는 단일 문구로 result_status와 새 분석 품질을 혼합하지 않는다. 기존 상태는 ‘판단 가능 범위’ 등 의미가 분명한 문구로 표시하고 새 검토를 별도로 보여준다. 저장된 결과를 표시하며 화면 진입·다운로드로 LLM을 호출하지 않는다.

디버깅 화면은 기록 생성 시각 정렬을 유지하면서 round/stage/input refs/analysis_id/decision refs로 단계 연결을 제공한다. 예를 들어 `D09 → 해석 → 초안 → 검토 → 추가 확인 필요 → D44`에서 query ID의 숫자 순서가 아닌 실제 선택 이유와 선행 기록을 열 수 있어야 한다. recorded_at은 생성 시각이며 조회 시작 시각·소요시간을 대신하지 않는다. 시작/종료·duration이 없는 구 기록은 값을 추정하지 않는다.

사람이 읽는 순서는 ‘무엇을 확인하려 했나 → 무엇을 했나 → 무엇을 알아냈나 → 남은 한계 → 연결 근거’다. 자료 수집/코드 판단/LLM 처리/원문·중간 결과 보존을 구분하고, 공통 역할 설명을 개별 수행 사유로 대신하지 않는다. `runbook`은 ‘선택 Runbook 원문 보존’이며 앞서 선택한 지침의 본문·revision·출처를 저장한 기록이다. 다시 실행했거나 적용 조건이 충족됐다는 뜻으로 표시하지 않는다. 후보 검색·제외, 이번 회차 조회 배정·예산은 한국어 설명을 먼저 보여주고 원문은 접는다. 미지원 구 기록은 알려지지 않은 의미를 추정하지 않는다. D계열은 조회 이름과 ID, 저장 계획의 목적·필수 여부, 실제 범위·기간과 수집 제한을 보여준다. 같은 analysis_id의 관련 기록은 연결하되, 목록에 입력 refs가 없는 후속 기록의 사용 관계는 시간 순서로 추정하지 않는다.

분석 상세의 ‘분석·검토 예산 배분’은 요청/적용 예약과 보호 하한·조정 사유를 설명한다. ‘근거를 분석 입력에 담기 위해 검토 예약의 일부를 조정했다’는 의미를 검토 성공으로 표시하지 않는다. 구 기록의 하한은 기록 없음으로 남긴다.

모델 호출의 실제 모델·stage·호출/전송 시도·사용 토큰·경과시간·제한된 입력 refs·생략 범위·구조화된 판정 이유를 표시한다. 비밀 값·원시 거절 응답·내부 사고 과정은 노출하지 않는다. 신규 결과는 최종 초안만 표시하고 이전·보류 초안은 디버깅 이력으로 구분한다. 최종 analysis_id와 다른 검토를 최신 통과로 표시하지 않는다. 원문은 기존 escape·접근 범위·크기 제한을 지킨다.

확장이 없는 과거 결과는 ‘평가 분리 기록 없음’, 지원하지 않는 버전은 ‘지원되지 않는 평가 형식’으로 표시하고 기존 내용 조회를 유지한다. 이를 검토 실패·타당으로 추정하지 않는다. 미공개 결과는 기존 공개 참조 계약을 따른다. fast path의 새 단계 생략과 기존 최종 편집 수행은 별도로 표시한다.

구현은 [RcaEvaluation](../../../frontend/src/components/RcaEvaluation.tsx)의 요약·척도와 [RcaEvaluationTrace](../../../frontend/src/components/RcaEvaluationTrace.tsx)의 단계·원본 연결, [RecordInspector](../../../frontend/src/components/RecordInspector.tsx)의 해석/검토 상세를 사용한다. 담당 LLM 단계와 실제 호출 횟수를 구분하고 round·analysis_id·reason·입력 생략을 표시한다. 추가 소비자는 [RcaDebug](../../../frontend/src/components/RcaDebug.tsx), [live](../../../frontend/src/components/live.tsx), [workflow 안내](../../../frontend/src/lib/workflow.ts) 및 관련 결과/보고서 표시다. 검수는 [05 T66~T79](../05_테스트_검수_기준서.md#rca-평가-분리-검수)를 따른다.

### 2026-10-12 보고서의 대용량 결과와 삭제

개발용의 원본/조회용 결과 펼침 영역은 닫힌 상태에서 JSON 트리를 생성하지 않고, 펼칠 때 생성한다. Backend가 생략 필드를 알리는 `result_projection`을 보낸 경우 원본 전체라는 표현 대신 조회용 결과와 생략 안내를 표시한다. 보고서를 전환하면 펼침 상태를 초기화한다.

종료된 운영 보고서에는 삭제 확인을 제공한다. 본문·전용 증거·파일이 삭제되고 최소 작업 이력은 남는다는 점을 확인창에서 설명한다. 삭제 사유를 입력하고 현재 버전과 멱등 키를 사용해 요청한다. 다른 기록에서 사용하는 증거가 있거나 실행 중이면 삭제할 수 없다. 실제 데이터 삭제가 실패한 경우 목록에서 먼저 지워 성공처럼 보이지 않게 한다. 삭제 후에는 결과 본문 대신 삭제 기록 및 파일 정리 상태를 표시한다.
