# 07. 프론트엔드 개발 명세서

## 범위와 구현 상태

기존·운영·개발자·신규 관점을 보존하고 개발 콘솔과 운영 콘솔을 추가한다. 여섯 관점은 같은 API·저장 결과를 사용한다. 구현은 로컬 변경이며 배포와 검증은 [Frontend QA](../../../frontend/QA.md)에서 별도로 확인한다.

화면 계약은 [08](08_GUI_화면설계서.md), API는 [02](../backend/02_백엔드_API_작업명세서.md), 공통 검수는 [05](../05_테스트_검수_기준서.md#여섯-탭-gui-검수)가 소유한다. 인증/RBAC, 별도 분석 엔진·큐·스케줄러, 수동 RCA, 장비 자동 조치와 기존 GUI 삭제는 범위 밖이다.

## 정보 구조와 코드 경계

| 영역 | 구현·호환 계약 |
|---|---|
| 모드 | [store](../../../frontend/src/lib/store.tsx)·[ViewMode](../../../frontend/src/components/ViewMode.tsx): classic / operations / developer / new / workbench / control. 기본 classic·기존 저장값 유지 |
| 화면 선택 | [Shell](../../../frontend/src/components/Shell.tsx)이 [NewWorkspace](../../../frontend/src/pages/NewWorkspace.tsx) 또는 [ConsoleWorkspace](../../../frontend/src/pages/ConsoleWorkspace.tsx)를 선택. 해당 경로에 필요한 화면만 마운트 |
| 개발 콘솔 | `/dashboard` 실패 기본·`/jobs` 전체 작업. 종류·상태·노드·사건·접수일 검색과 선택 작업 진단. 상세는 JobDebug·TraceView 재사용 |
| 운영 콘솔 | 기간 제한 없는 미종결 사건과 전체 이력, 사건 안에서 RCA 읽기·검토·처리. 분석 기간 겹침으로 Ops 검색하고 저장된 변화·한계 미리보기 |
| 사건 API | 페이지별 rca_summary를 사용하며 각 행의 상세를 순회 조회하지 않음. 요약 부재는 미확인 |
| 결과 | RcaNarrative·AggregateReport·BasicReport·ReportStatements·기존 그래프 재사용. 미발행 후보는 표시하지 않음 |
| 기록 | NewReviews의 사건·보고서별 의견/실제 조치/정정. 분석별 과거 job 기록은 읽기 전용으로 보존. 실제 조치 대상은 해당 저장 범위와 수행 시각의 자산에서 선택 |
| 명령 | 기존 버전·멱등·can_*·삭제 참조 보호 계약 유지. GUI에서 Worker로 직접 요청하지 않음 |

관점 전환은 현재 경로를 유지한다. 개발 콘솔의 작업 상세는 입력·출처 / 실행·시도 / 근거·데이터 / 결과·공개로 나뉘며 탭·선택 시도·근거·복귀 필터를 URL로 보존한다. 워크플로우 팝업도 같은 선택을 사용하며 설정을 점검한 뒤 원래 작업으로 복귀한다. 목록의 종류·상태·검색·기간을 바꾸면 선택 작업 진단을 해제한다. 운영 콘솔에서는 사건·보고서의 읽기·기록 경로를 제공한다. 모드가 인증·권한을 부여하는 것으로 설명하지 않는다.

신규(new)의 세 메뉴·개발 경로 전환 안내는 유지한다. 신규·운영 콘솔의 결과 읽기에서 원문 JSON·내부 키·모델 실행 진단을 기본 본문에 섞지 않는다. 같은 결과의 개발 상세로 전환해 진단할 수 있다.

## API와 상태 표시

- 사건 발생·알림 해제·처리 상태·사람의 검토를 분리한다. 최신 실행 상태와 마지막 공개 결과 품질도 독립적이다.
- 실행 완료가 공개 결과·원인 확정·조치 완료를 보장하지 않는다. 설명 실패 시 저장 관측을 읽되 기본 보고서를 성공한 해석으로 표현하지 않는다.
- 클러스터 없음·자료 없음·연결 실패·미지원 Backend를 구분한다. 빈 목록이나 없는 표본을 정상으로 표현하지 않는다.
- 운영 콘솔 사건 기본값 `unclosed`는 `open`·`acknowledged`를 기간 제한 없이 조회한다. 전체 이력·개별 처리 상태의 기간은 발생 시각이며 정렬은 접수 최신순이다. 작업 검색 기간은 작업 접수 시각이다.
- 보고서 분석일 검색은 `analysis_from`·`analysis_to`와 저장된 분석 기간의 겹침을 사용한다. 날짜 끝은 KST 다음 날 0시 미만이며 접수일 `from`·`to`와 독립적이다. 분석 기간 미기록·잘못된 구 결과는 날짜 검색에 포함하지 않고 조건 해제 후 읽기를 유지한다. 상세 범위와 기간은 저장 당시 값이다.
- 보고서 목록의 `report_preview`는 저장된 요약·관측 한계·누락 자료의 발췌다. `method`와 `narrative_status`를 함께 확인해 AI 해석·AI 우선선택·계산 요약을 구분하고 부재·잘림을 표시한다. 전체 본문이나 새 해석으로 표현하지 않는다.
- 목록 필터와 cursor를 기존 API로 전달하고 추가 페이지를 사용자 조작으로 읽는다. 불러온 일부 항목만으로 전체 합계·위험 순위를 만들지 않는다.
- 원문 조회는 job/attempt 또는 knowledge/revision/hash를 확인한다. 불일치·404·오류를 현재 데이터로 대체하지 않는다.
- 고정 버전은 결과 발행 전에도 trace에서 조회한다. 지식 후보는 실제 선택·사용 여부와 구분하고 현재 설정을 당시 설정으로 대체하지 않는다. 시도 비교는 같은 작업의 선택 시도와 직전 기록이며 미기록을 성공으로 보충하지 않는다.
- 새 RCA 의견·검토·조치 기록은 incident에 남긴다. 분석본 직접 링크는 연결 사건과 해당 분석 선택을 함께 전달한다. 분석별 이전 job 기록은 이동·병합하지 않으며 기록 저장이 검토 완료·사건 종결을 자동 변경하지 않는다.
- 서버 문자열은 React escape를 유지한다. API 관찰에는 본문·쿼리 값·비밀을 기록하지 않는다. 내부 반환 경로만 허용한다.

## RCA 평가 분리 표시

현재 RCA는 한 번 수집하고 통합 작성과 최종 보고서 작성으로 이어진다. 별도 검토·목표 평가·추가 수집 루프는 현재 실행 경로가 아니다. 생산자 규칙은 [RCA README](../../../rcca-agent/README.md)를 따른다.

과거 결과의 해석·분석·검토·수정·선택·목적 판정 진단은 호환 읽기 대상으로 남긴다. 저장된 review envelope나 skipped 상태를 실제 검토 호출로 설명하지 않는다. 과거 결과를 새 workflow로 재작성하지 않는다.

워크플로우 디버깅은 같은 작업/시도의 저장 기록을 생성 시각과 계획 순서로 보여주고 입력 refs·analysis_id·revision으로 연결한다. 상세↔팝업 이동에서 시도·선택 근거를 유지하고 없는 시도를 최신으로 대체하지 않는다. 기록 생성 시각을 실행 시작 시각으로 대체하거나 단순 시간 순서로 사용 관계를 추정하지 않는다. 요청/응답 횟수, 입력 크기, usage, 실패 사유와 미기록은 구분한다.

운영 본문은 확인한 사실·원인 후보·확인하지 못한 사항·다음 확인부터 읽게 한다. 저장된 주장·수치·한계를 보존하며 공통 대응 절차는 보조 영역으로 접는다. 비어 있는 사실·후보·한계를 임의 생성하거나 일반 Runbook 설명을 해당 사건의 확정 원인으로 바꾸지 않는다.

| 항목 | 표시 경계 |
|---|---|
| 수집 | 완료·부분·실패·생략과 저장 사유. 빈 응답은 장비 정상 아님 |
| 분석 | 저장된 관측·해석·한계. 일부 채택·기본 보고서·해석 실패를 구분 |
| 과거 검토 | 실제 기록이 있는 경우만 미검토/수정 필요/판단 불가 등을 표시 |
| 원인·조치 | 기존 causal_status·권고 자격·수행 기록을 유지. 분석 완료로 승격하지 않음 |
| 실행 | JC attempt 종료와 Incident 종결·장비 회복은 별도 |
| 결과 | 발행 참조를 확인하고 공개되지 않은 후보 본문은 읽지 않음 |

## 회귀 검증

- 여섯 관점의 순서·기존 저장값·직접 URL·입력 중 이탈·모드 전환을 확인한다.
- 개발자 관점: 노드·사건·접수일 검색 → 선택 작업 진단 → 이전/현재 시도 비교 → 같은 시도의 팝업·근거 → 고정 버전과 현재 설정 점검 → 원래 필터·선택 복귀. 필터 변경의 선택 해제·ID 직접 조회·연결 정보 불일치도 확인한다.
- 운영자 관점: 24시간보다 오래된 미종결 사건, 최신 조사 진행 중+과거 공개 RCA, 사건 중심 기록과 별도 검토 상태 변경, 분석일과 접수일이 다른 보고서 검색, 부분 보고서 요약·한계·미발행·삭제, 생성·일정·출력.
- 실패·접근성 관점: 390px·키보드·터치 영역·긴 표, API 오류/재시도/빈 목록, 선택 범위 표시, 누락값 의미.
- 기존 네 관점과 결과 컴포넌트 회귀, API 요청 필터·범위·부족 근거 및 구 기록 호환을 유지한다.
- `npm run format:check`, `npm test`, `npm run build`와 실제 브라우저 시나리오를 실행한다. fixture와 실제 Backend/DB 결과를 구분하고 운영 Grafana·LLM·배포 미검증을 명시한다.
