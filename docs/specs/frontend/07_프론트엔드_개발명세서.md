# 07. 프론트엔드 개발 명세서

## 보고서 기간·수집 구간 표시 — 2026-10-01

요청 직전에 입력한 시작/종료·시간 길이(정기는 직전 완료된 일/주/월)를 보여준다. 실제 수집 한도와 초기 조회량은 Worker가 관측 전에 검사하며 접수 화면에서 성공을 보장하지 않는다. 결과의 `quality.collection`이 있으면 계획 중단/전체 구간 응답 완료/일부 미완료, 초기 계획·실제 조회량을 표시한다. 분석 진행 상세에서 query+CPC+비교 기간별 요청 범위, 데이터 응답·빈 응답·미완료 시간, 각 구간의 상태/사유/근거를 확인한다. 조회 응답 시간은 GPU 사용시간·원본 표본 커버리지가 아니다. 구 결과에 없는 진단은 추정하지 않는다.


## 보고서 요청·이력·진단 — 2026-10-01

기본 화면은 전체 보고서 이력이다. 기존·운영·개발 관점에서 `보고서 이력 / 정기 일정` 두 탭과 `새 보고서 만들기` 버튼을 사용하며 실행 상태·주제는 필터로 선택한다. 기존 `?tab=final` 링크는 완료 필터로 계속 열린다. 성공 상태와 공개 참조·결과 품질은 별개다. 보고서 전용 표에서는 종류·중복 결과 링크 열을 제거하며 일반 작업 표와 RCA 경로는 유지한다.

신규 요청은 전체 종합(초기 선택) 또는 7개 목적별 종류를 다중 선택한다. 합집합 O01~O11을 하나의 보고서 소주제로 표시하고 카드·결과에 실제 계산 기준을 안내한다. [02 입력 계약](../backend/02_백엔드_API_작업명세서.md#소주제별-기준을-가진-보고서--2026-10-06)의 topic_group_by와 [12번 종류 표](../ops-agent/12_보고서_Agent_모듈_설계서.md#보고서-선택-개편-전-확정-기준--2026-10-06)를 따른다. 조건 부족 주제도 이유와 함께 유지한다. O10 비교 입력은 직접 요청에서 선택하며 자동보고서에서 임의 생성하지 않는다. 기존 일정/결과·O ID·일자 입력은 유지한다. 이는 수집량 감소나 일반 group_by 구현 완료를 뜻하지 않는다.

O10은 수행 조치 ID와 비교 기간이 필수인 직접 요청으로만 제공하고, O07은 선택 자원 조건을 표시한다. 종류 변경 시 조치·비교·자원 조건을 비운다. 나머지 종류는 기존 일간/주간/월간 자동보고서 등록을 사용한다. 기존 일정 편집은 주기·시각만 보내며 report_spec을 새 종류로 치환하지 않는다. 과거 임의 조합과 저장 결과는 그대로 표시한다. Namespace 활동은 관측 GPU의 활동이며 실소비량·독점 할당량·회수 가능량을 뜻하지 않는다.

목록 제목은 O08/namespace 단독이면 목적명, 복수 주제면 `GPU 운영 보고서 · N개 주제`로 줄이고 실제 주제·대상·기간·집계를 보존한다. 일정 목록은 UUID 대신 저장된 이름 또는 분석 목적과 주기·대상을 표시하고 revision/ID는 상세에 남긴다. 보고서 제목은 공개 참조가 있으면 본문으로, 없으면 작업 상태로 이동한다. 보고서 목록에서 진입한 결과/작업 상세의 `목록으로`는 기존 필터와 불러온 목록의 해당 행 위치를 복원한다. 직접 URL 진입·목록 데이터 변경으로 해당 행이 없으면 위치 복원은 보장하지 않는다.

본문의 `#final-report`는 한국어 분석 요약부터 시작한다. 저장된 LLM/기본 보고서 문구는 `저장된 보고서 해석`에 접어 보존하며 수치·상태·권고·원문을 재작성하지 않는다. `분석 진행 상세`는 기본 접힘이며 주제별 산출/산출 불가, 부족 사유와 원본 코드, 권고 보류, 기록된 query/CPC의 수집 상태와 다음 확인, 원본 수집 기록·근거를 연결한다. 이는 실시간 단계 로그가 아니다. 조회 기록 부재를 미조회/데이터 없음으로 추정하지 않는다. 수집 완료도 계산·권고 가능을 보장하지 않는다. 다음 확인은 저장 상태에 따른 점검 안내이며 확인된 장애 원인이나 자동 조치가 아니다. 수집 합계는 기존 중복 제거 규칙을 유지한다.

Backend·Agent·DB·조회 한도·API 계약·HTML/CSV 다운로드 내용은 변경하지 않는다. 화면은 같은 결과의 읽기 순서와 진단 노출만 바꾼다.

## 최종 보고서 접근·표시 — 2026-09-30

RCA 첫 페이지(`/cases`)의 버튼과 `최종 보고서` 탭에서 공개 RCA 결과에 접근한다. 기존·개발·운영 관점에 적용하며 실행 성공과 결과 품질은 구분한다. 공통 작업 목록은 `result_ref`가 있는 RCA/Ops에만 `최종 보고서 보기` 링크를 표시한다. 미발행은 진행 상태만 표시하고 구 결과도 기존 상세 화면으로 열린다. 보고서 hash 링크는 데이터가 로드된 뒤 해당 섹션으로 이동한다.

Ops의 다섯 섹션 narrative는 위 2026-10-01 기준에 따라 접힌 해석 영역에 보존하고 LLM 편집과 결정적 기본 보고서를 구분한다. Namespace 요약/단위/부분 산출 표시를 유지하며 구 narrative는 기존 방식으로 읽는다. 문자열은 React로 escape한다. Worker/Backend HTML도 같은 저장 narrative를 사용하고 CSV 계산값은 유지한다.

## 2026-09-30 RCA 최종 보고서 표시

공개된 RCA의 `narrative`를 감지된 문제·원인 판단·권고 조치와 조건·추가 확인·분석 한계로 표시한다. `narrative_status=complete`는 LLM 문장 우선순위 편집, failed/omitted는 코드 기본 보고서로 안내한다. 보고서 작성 완료를 원인 확정·조치 수행·장비 복구로 표시하지 않는다. 미발행 결과는 숨기며 기존 narrative 없는 결과는 기존 상세 표시를 유지한다. React로 원문을 escape하고 줄바꿈 문단을 보존한다.

버전 1.3 · GUI는 Backend `/api/v1`을 호출한다. `775ab2f` 기준 서버 연결·클러스터 등록·보고서 화면의 구현 변경을 반영했다. 실제 실행 검증 범위는 [Frontend QA](../../../frontend/QA.md)를 따른다.

## 공통 상태·데이터

scope는 CPC별 Namespace 필터다. 로그인·역할 전환·권한 grant 기반 캐시·사용자 tenant UI는 이번 구현 기준에 포함하지 않는다. 입력/target/기간 검증과 모델 비밀 미노출은 유지한다.

캐시 키는 리소스·scope·기간·ID·revision을 포함한다. 범위 변경 시 이전 응답이 새 범위에 섞이지 않게 요청 취소 또는 응답 키 대조를 한다. 차트 간격 변경은 저장 분석 수치를 재계산하지 않는다.

job.status, result_status, topic/assessment status, quality, narrative_status를 각각 표시한다. queued의 capacity_wait는 '처리 자원 대기', worker_unavailable는 '실행 Agent 대기', inference_quarantined는 '추론 종료 확인 대기'로 구분한다. 0개 Agent에서도 접수된 잡을 실패로 바꾸지 않는다.

## 접수·폴링·명령

보고서 제출마다 멱등 키를 만들고 응답 확인 전까지 동일 요청에 재사용한다. 네트워크 실패 후 새 키로 다시 만들지 않는다. 202와 job_id를 받은 후 작업 상세로 이동한다. 입력을 수정해 의도적으로 다시 요청할 때만 새 키를 만든다.

queued/running/retry_wait를 운영 설정 간격으로 폴링하고 오류에는 backoff/Retry-After를 따른다. terminal이면 중단한다. 탭/화면 닫기는 잡 취소가 아니다. Backend의 can_cancel/can_retry를 표시하되 RCA에는 실행·재시도 버튼을 만들지 않는다. 명령은 별도 멱등 키+If-Match, 409면 상태 재조회·사유 표시다.

결과가 없으면 준비 중/종료 사유를 표시한다. succeeded+blocked도 가능하다. LLM 설명 실패만으로 수치·근거를 숨기지 않는다. 저장된 value_refs와 단위·기간을 사용하며 FE에서 같은 산식을 다시 구현하지 않는다.

## 정기 일정·출력·설정

정기 요청은 schedule_id/revision·시간대·다음 시각·실제 분석 기간을 보여준다. occurrence pending은 Backend 전달 대기, accepted는 JC job 연결, missed/failed는 사유와 함께 표시한다. 일정 일시중지는 이미 접수된 잡을 취소하지 않는다는 문구를 둔다.

보고서는 HTML/CSV를 Backend에서 다운로드한다. 지식의 검토/발행 상태와 content_hash 변경을 반영하고 발행본 직접 수정은 금지한다. 모델 라우팅은 rca/report만 표시한다. 연결 검사의 성공과 분석 품질 합격은 별개다. 용량/배포 수는 상태 조회만 제공하고 GUI 수정 버튼을 만들지 않는다.

## 클러스터 등록과 보고서 표시의 현재 구현

등록된 클러스터가 없으면 공통 화면은 등록 안내를 표시하고 `/settings/data`로 연결한다. 연결·설정 화면은 scope 선택 전에도 열 수 있다. 등록 모달은 실제 관측 라벨과 같은 cluster_id를 입력받아 멱등 키와 함께 `POST /clusters`를 호출한다. 중복/입력 오류는 서버 메시지를 표시하며 등록 성공을 수집 성공으로 표시하지 않는다. 구현: [Shell](../../../frontend/src/components/Shell.tsx), [설정](../../../frontend/src/pages/Settings.tsx).

보고서 상세는 기간·범위, 전체 수치 항목 중 산출 가능한 항목 수, 주제별 수치·대상·단위·부족 사유를 표시한다. null은 ‘산출 불가’이며 0과 구분한다. GPU–Pod 연결 관측 시간과 독점 할당 시간을 다른 이름으로 표시하고 원본 결과는 접을 수 있는 영역에 둔다.

수집 요약은 query_id·cluster_id별로 조회 구간의 상태·사유·표본 수를 묶고 여러 주제가 재사용한 동일 조회 묶음은 한 번 표시한다. 표본 수 표시는 원격 응답 건수의 합이며 경계 중복 제거 후 고유 표본 수와 다를 수 있다. LLM 설명이 failed/omitted여도 계산 수치와 근거는 유지한다.

발행 결과가 있으면 상세 상단에 HTML/CSV 다운로드 버튼을 표시한다. Backend 응답을 파일로 내려받고 오류는 화면에 표시한다. 수치 필드는 [03](../common/03_데이터_설계서.md), 다운로드 계약은 [02](../backend/02_백엔드_API_작업명세서.md)에 둔다. 구현: [보고서 표시](../../../frontend/src/components/ReportContent.tsx), [조회 품질 요약](../../../frontend/src/lib/report.ts), [결과 화면](../../../frontend/src/pages/Results.tsx).

일반 HTTP에서도 멱등 키·요청 hash 생성이 가능하도록 UUID는 getRandomValues, SHA-256은 설치된 해시 구현을 사용한다. 원본은 [browserCrypto](../../../frontend/src/lib/browserCrypto.ts)다. 기존 QA의 과거 데모 기록은 날짜별 현행 검증과 구분하며 이번 문서 갱신을 새 실행 시험으로 기록하지 않는다.

## 보고서 개선 조언 소비 — 2026-09-30 개발 목표

[12](../ops-agent/12_보고서_Agent_모듈_설계서.md)의 OP-07과 기존 결과 스키마로 S10을 보완한다. 통계·공개 RCA 요약·개선 권고·보류 항목·품질/한계를 구분하고, 권고의 대상·사실/근거·전제·다음 행동/확인 방법을 표시한다. value_refs로 저장 수치를 참조하며 새 산식이나 절감 효과를 계산하지 않는다. eligibility=withheld는 보류 사유와 확인 사항으로, execution=not_performed는 미수행 권고로 표시한다. Agent 권고를 실제 조치나 자동 실행 버튼으로 바꾸지 않는다.

job의 succeeded, topics의 partial/blocked, narrative_status의 failed/omitted, 권고 자격은 별개다. 구 보고서의 권고 필드 부재는 없는 상태로 처리하고 LLM 설명 실패에도 유효 통계·코드 판단을 유지한다. 병렬 Sub-agent는 별도 사용자 작업/일정으로 표시하지 않으며 조회 품질 요약은 재사용 근거를 중복 집계하지 않는다. Backend HTML과 권고·보류·근거가 일치하고 CSV 수치/단위/기간이 일치하는지 [05 T65](../05_테스트_검수_기준서.md)에서 검사한다. 현재 화면의 구현 완료를 뜻하지 않는다.
