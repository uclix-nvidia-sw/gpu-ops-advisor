# 08. GUI 화면설계서

## 2026-09-30 RCA 최종 보고서 표시

공개된 RCA의 `narrative`를 감지된 문제·원인 판단·권고 조치와 조건·추가 확인·분석 한계로 표시한다. `narrative_status=complete`는 LLM 문장 우선순위 편집, failed/omitted는 코드 기본 보고서로 안내한다. 보고서 작성 완료를 원인 확정·조치 수행·장비 복구로 표시하지 않는다. 미발행 결과는 숨기며 기존 narrative 없는 결과는 기존 상세 표시를 유지한다. React로 원문을 escape하고 줄바꿈 문단을 보존한다.

버전 1.3 · 화면별 기준과 `775ab2f`의 클러스터 등록·보고서 표시 변경을 기록한다. 전체 화면의 실환경 검수 완료를 뜻하지 않는다.

현재 코드와 아래 화면 목표의 차이, 구현 순서와 검수 사례는 [07 §0](07_프론트엔드_개발명세서.md#0-현재-구현-분석과-업그레이드-작업)에서 관리한다. 특히 S05/S07의 사건 상태 정합·종결 입력·RCA 근거/에피소드 표시는 추가 개발 대상이며 아래 필수 내용이 모두 구현됐다는 뜻이 아니다.

## 공통 화면 틀

좌측 메뉴·상단 CPC/Namespace 필터·기간/시간대·본문을 둔다. 채팅/Assistant·프로필 역할 전환·수동 RCA 실행 버튼은 없다. 상단에 데이터 기준 시각과 부족/오류를 표시한다. 사건/잡/결과의 ID가 다른 경우 모두 연결한다.

| 화면 | 필수 내용 | 행동 | 빈 상태·검수 |
|---|---|---|---|
| S01 대시보드 | 사건 현황·관측 품질·최근 보고서·큐 대기 | 사건/보고서/작업 상세 이동 | 지표 없음과 유효 0 구분 |
| S02 장비/GPU | cluster·Node·GPU UUID·모델·현재 상태/시각 | 필터·추이·관련 사건 보기 | 매핑 미확인을 미할당으로 표시 금지 |
| S03 작업 연결 | Pod UID·배치·GPU 관계·활동 각각 표시 | 관련 장치/사건 조회 | bound Pending과 unbound 구분 |
| S04 관측 품질 | 필수 입력·공동 관측률·신선도·미확인 범위 | 근거·대상별 부족 원인 조회 | 분모 미확인은 null+사유 |
| S05 RCA 사건 목록 | 사건 시각·대상·심각도·state·RCA job/result 상태 | 사건 열기·검색 | '새 조사' 없음, 사건 없으면 알람 연동 상태 안내 |

| S08 보고서 목록 | 주제·분석 기간·생성 경로·상태 | 즉시 요청/정기 일정/결과 이동 | 첫 보고서 요청 안내 |

| S09 일정 목록/상세 | 빈도·시간대·예정일·revision·next_run·발생 목록 | 생성·수정·일시중지/재개 | pending/accepted/missed/failed 구분 |

## 주요 흐름

RCA는 알람 → 사건 생성 → RCA 큐 → Agent 처리 → S05/S07 조회다. 화면에서 새로운 RCA를 생성하지 않는다. 실행 대기 중에는 사건·원문을 먼저 조회할 수 있다.

즉시 보고서는 S08 → S09 입력 → 202/job_id → S11 진행 → S10 결과다. 정기 보고서는 S09 일정 → Backend occurrence → 동일 보고서 큐 → S10 결과다. 일정 발생 이력과 job 실행 이력을 따로 연결한다.

## 상태 문구

| 서버 상태 | 문구·행동 |
|---|---|
| queued + capacity_wait | 처리 자원을 기다리는 중. 요청은 저장됨 |
| queued + worker_unavailable | 실행 Agent를 기다리는 중. 운영 상태 확인 |
| running | 처리 단계·시작 시각·마감 표시 |
| retry_wait | 일시 오류로 재시도 대기, 기존 job 유지 |
| succeeded + partial/blocked | 처리 완료. 일부/전체 분석 근거 부족, 상세 이유 제공 |
| narrative_status=failed/omitted | 설명 생성 실패/생략, 유효 수치·근거는 표시 |
| failed/cancelled/expired | 종료 사유·시도 이력, 가능한 보고서 명령만 표시 |

## 현재 화면의 상세 기준

S15 등록 모달은 cluster_id 한 항목을 입력받으며 Grafana의 실제 클러스터 라벨과 같은 값을 사용한다. 별도 datasource 주소 입력란은 없다. 미등록 상태의 안내와 등록 성공/오류 처리는 [07](07_프론트엔드_개발명세서.md)에 둔다.

S10은 관측 GPU 수·GPU–Pod 연결 관측 시간·독점 할당 시간을 구분한다. Namespace별 연결 관측 시간은 공유 GPU 때문에 합계가 중복될 수 있다는 사유를 표시한다. 수집 실패·한도 초과·데이터 없음은 조회별 상태와 사유로 확인한다. 상세 필드·출력은 03/07/02를 참조한다.

2026-09-30 S10 추가 개발 목표: 통계와 공개 RCA에 연결된 개선 권고, withheld 사유·전제·다음 확인을 구분해 표시한다. 미수행 권고를 실제 조치로 표시하지 않고 설명 실패 시에도 유효 수치를 유지한다. 구 결과의 권고 부재·미공개 결과도 처리한다. 병렬 관측은 내부 실행 구조이므로 별도 접수/서브 에이전트 제어 화면을 만들지 않는다. 상세는 [07의 소비 기준](07_프론트엔드_개발명세서.md), 검수는 [05 T65](../05_테스트_검수_기준서.md)를 따른다.

수동 RCA 접수·대화·사용자 역할 선택 화면은 제공하지 않는다. 저장된 RCA 결과 조회 경로는 유지한다. 기존 화면 ID는 참조용으로 보존하며 검수는 05의 T28/T29와 접근성·새로고침·출력 일치 기준을 따른다.
