# 08. GUI 화면설계서

## 문서 범위와 상태

**기존 / 운영 / 개발자 / 신규 / 개발 콘솔 / 운영 콘솔의 여섯 관점을 제공한다.** 기존 네 관점은 보존하고 개발 진단과 운영 판단에 맞춘 두 콘솔을 추가한다. 로컬 구현·검증·배포 상태는 README·QA에서 구분한다.

현재 코드 대조·API 계약은 [07](07_프론트엔드_개발명세서.md), 실행된 검증은 [Frontend QA](../../../frontend/QA.md), 검수 시나리오는 [05](../05_테스트_검수_기준서.md#여섯-탭-gui-검수)에서 관리한다. 기존 네 관점은 비교용으로 보존하며, 저장 데이터와 개발용 기능의 호환 계약은 유지한다.

## 정보 구조와 역할

기존(classic)·운영(operations)·개발자(developer)의 메뉴·화면·기본값을 유지한다. 다음 세 메뉴와 표시 규칙은 신규(new)에만 적용한다. 디버깅에 유용한 보완은 개발자 탭에 추가할 수 있다.

| 구분 | 메뉴 | 목적과 범위 |
|---|---|---|
| 신규 | 운영 현황 | 선택 기간의 최근 사건과 범위 내 최근 보고서로 진입. 부분 목록에서 전체 총계를 만들지 않음 |
| 신규 | 사건 분석 | 사건별 발생 내용·공개 RCA·한계·권고·검토 및 실제 조치 기록 |
| 신규 | 운영 보고서 | 보고서 목록·생성·결과·자동 보고서 설정 |
| 신규 보조 | 이용 안내 | 용어와 사용법. 별도 업무 메뉴로 승격하지 않음 |
| 개발용 | 기존 개발측 메뉴 유지 | 관측·신원, 사건·RCA, 보고서·일정, 작업 디버깅, Runbook·revision, 연결·구성 |

신규는 운영 결과를 읽고 요청·기록을 남기는 화면이며 읽기 전용으로 축소하지 않는다. 모드 전환은 표시 구성의 선택이며 인증·권한·RBAC가 아니다. 개발용 제거, 장비 제어, 수동 RCA 실행·재시도는 이번 범위가 아니다.

## 개발·운영 콘솔

| 관점 | 첫 화면과 메뉴 | 상세·조작 |
|---|---|---|
| 개발 콘솔 (workbench) | 실패 진단(`/dashboard`, 실패 기본)·전체 작업(`/jobs`). 노드·사건·접수일·종류·상태 검색, Job ID 직접 조회. 자산·사건·보고서·Runbook·설정 메뉴 | 목록의 단계·종료 사유와 선택 작업 진단, 고정 입력·시도 비교·근거·발행 결과. 상세와 설정 방문 후 같은 검색 조건·선택으로 복귀 |
| 운영 콘솔 (control) | 운영 개요, RCA 사건, Ops 보고서, 자동 보고서. 미종결 사건 우선과 분석일 기준 보고서 탐색 | 같은 사건 안에서 RCA 읽기·처리·검토, 보고서 저장 요약·한계 확인. 생성·출력·일정은 기존 명령 계약 유지 |

개발 목록은 선택한 작업의 진단 패널을 연다. 종류·상태·노드·사건·접수일 조건이 바뀌면 선택을 해제하며 작은 화면에서는 열린 진단으로 포커스를 옮긴다. 전탭 상단에서 실행 시도를 선택하고 팝업과 URL의 시도·근거를 공유한다. 선택 시도와 직전 시도의 차이를 대조하며, 결과 발행 전에도 고정 입력·모델·실행 프로필 revision을 읽는다. 고정 지식 후보 목록과 원본은 펼쳐 확인한다. 현재 설정은 당시 설정과 구분하고 조사 중인 작업으로 돌아오는 링크를 제공한다.

운영 개요와 RCA 사건의 기본은 발생일 제한 없는 미종결(`open`·`acknowledged`) 사건이다. `전체 이력` 또는 개별 처리 상태를 선택하면 발생일 검색을 제공한다. 발생일 필터와 접수 최신순 정렬을 구분하며 알림 해제를 사건 종결로 취급하지 않는다. 보고서는 분석 대상일과 저장된 분석 기간이 겹치는 요청을 찾고, 상태·주제·접수일은 보조 조건으로 둔다. 날짜 조건별 해제와 모든 조건 해제를 구분한다.

두 콘솔은 검정·회색·녹색의 절제된 스타일을 사용한다. 색으로만 상태를 구분하지 않으며 제목·링크·버튼이 목적지를 설명한다. 모바일의 관점 전환과 조작 영역은 최소 44px 높이로, 긴 표는 내부 스크롤로 제공한다. 선택한 클러스터 범위는 좁은 화면에서도 보인다. 운영 상세에는 적용되지 않는 전역 기간 선택을 표시하지 않는다.

이하 신규 전용 상세 구성은 운영 콘솔의 사건·보고서 상세에서도 재사용한다. 개발 콘솔은 기존 개발용 원문·진단 기능을 유지한다.

## 공통 화면 틀

- 상단은 제품명·현재 위치·여섯 탭 선택이다. 신규(new)의 주 메뉴는 위 세 개이며 두 콘솔은 역할별 메뉴를 사용한다. DB·로컬 개발 환경 문구는 개발용으로 옮긴다.
- 목록·운영 현황에는 클러스터/Namespace 범위와 실제 적용되는 기간·필터만 둔다. 신규(new)의 사건 기간은 발생 시각, 보고서 목록 기간은 요청 접수 시각이다. 운영 콘솔의 미종결·분석일 검색은 위 콘솔 규칙을 따른다. 보고서 본문의 분석 기간은 별도로 표시한다.
- 사건·RCA·보고서 상세는 저장된 대상·시각·분석 기간을 표시한다. 전역 최근 시간 선택으로 저장 결과를 다시 계산하는 것처럼 보이지 않게 한다.
- 제목 → 한 줄 결론 → 상태 → 본문 → 추가 근거의 위계를 둔다. 기존 표·그래프·단위·의미를 재사용하고 긴 표는 표 내부에서 스크롤한다.
- 신규에는 원본 JSON·DB 키·attempt·토큰·query ID·모델/Runbook revision을 렌더링하지 않는다. CSS로 가리거나 접힌 디버깅 트리를 남기는 방식으로 처리하지 않는다.
- 노드명·Namespace·운영에 필요한 오류 코드와 핵심 관측은 유지한다. 내부 키를 숨기는 것과 대상 장비를 식별할 정보를 없애는 것을 구분한다.
- 결론을 제한하는 자료 부족과 조치의 전제는 처음부터 보인다. 보충 자료만 펼침 영역에 둔다.

### 링크와 기능 탐색

- 링크는 누르기 전에 목적지를 알 수 있어야 한다. `전체 보기`·`이전 화면` 대신 `사건 목록 보기`·`보고서 상세로 돌아가기`처럼 실제 목적지를 표시한다. 복귀 링크는 기존 필터와 돌아온 경로를 보존한다.
- 사건·보고서의 클릭 가능한 제목과 본문 이동 링크는 기본 상태부터 밑줄로 구분한다. hover나 색상만으로 링크 여부를 전달하지 않는다.
- 보고서 목록·상세·생성, 자동 보고서 목록·상세, 읽는 방법에 동일한 `보고서 목록 / 자동 보고서 설정 / 보고서 읽는 방법` 메뉴를 유지하고 현재 영역을 표시한다.
- 사건 상세는 긴 분석 본문 앞에 분석 결과·조사 이력·처리 상태·검토/조치 기록 바로가기를 둔다. 같은 페이지의 목차를 눌러도 원래 출발 화면과 복귀 필터를 보존한다. 실행 내역·보고서 결과 앵커는 응답이 늦어도 본문 로딩 후 해당 위치로 이동한다.
- 자동 일정 목록은 `일정 상세·편집`과 `실행 내역 보기`를 구분한다. 일정에서 보고서를 열면 해당 일정으로 돌아갈 수 있어야 한다.
- 조치 저장이 불가능하면 빠진 필수 항목을 저장 버튼 옆에 표시한다.
- 한 번 생성하는 보고서와 반복 일정의 진입을 구분한다. 일정 추가는 `자동 보고서 일정 추가`로 표시하고 돌아가기 목적지는 자동 보고서 설정 목록이다.
- 기능을 찾을 때 메뉴 이름과 목적지가 맞는지, 직접 URL·오류·빈 화면에서도 다음 이동 경로가 보이는지 검수한다. 구현·브라우저 확인만으로 처음 사용하는 사람의 탐색 성공을 입증했다고 기록하지 않는다.

## 화면별 기준

### S01 운영 현황

선택 범위·기간의 사건 수, 최근 접수 사건, 최근 요청 보고서와 각 목록/보고서 생성 진입을 제공한다. 실시간 GPU 상태판을 새로 만들지 않는다. 사건 행은 S05와 재사용하고 보고서는 미발행 요청도 숨기지 않는다.

기존 `/dashboard` 응답의 jobs 수는 RCA·보고서 합계이므로 장애 분석 수로 이름을 바꾸지 않는다. 운영 콘솔 개요는 일부 미종결 사건과 최근 보고서이며 전체 미검토 수가 아니다. 실시간 건강도·위험 점수·미검토 총계는 필수 지표에서 제외한다. 자료 부재는 정상/0이 아니다.

### S05 장애 분석 목록

- Incident 한 건을 한 행으로 표시한다. 같은 사건의 RCA 작업을 사건처럼 중복 표시하거나 별도 에피소드를 임의 병합하지 않는다.
- 기본 열은 발생 시각, 클러스터/노드, 발생 내용, 알림 상태, 분석 상태, 검토 상태다. 사건 처리 상태도 별도로 식별 가능하게 표시한다.
- 범위·발생 기간·사건 처리 상태 필터를 우선 제공한다. 정렬은 현재 API의 접수 순서이며 발생 순이라고 표기하지 않는다. 미지원 검색·검토/분석 상태 필터를 현재 페이지에만 적용해 전체 검색처럼 제공하지 않는다.
- 단일 주 링크는 `/incidents/:id`다. 신규 목록에는 조사 이력/최종 보고서 중복 탭이나 작업 ID 링크를 두지 않는다.
- 최신 실행과 최신 공개 결과를 분리한다. 새 분석 중 이전 공개 결과가 있으면 두 사실을 함께 표시한다. 요약 필드 미제공은 분석 상태 미확인이다.
- 사건 0건, 조회 실패, 분석 미접수는 구분한다. 사건 없음으로 관측 정상이나 알람 연동 성공을 선언하지 않는다.

분석 요약은 목록 응답의 `rca_summary`를 사용한다. [Backend 조회 계약](../../../backend/API.md)에 따라 행마다 상세를 호출하지 않으며 서버가 요약을 제공하지 않으면 미확인으로 표시한다.

### S07 사건과 장애 분석 결과

| 순서 | 내용 | 표현 규칙 |
|---|---|---|
| 1 | 발생 내용 | 저장된 증상·대상·발생/수신 시각. 현재 실시간 상태와 구분 |
| 2 | 사건 판단 | 확인한 사실·원인 후보·확인하지 못한 사항·다음 확인. 저장된 판단 수준과 한계를 유지 |
| 3 | 상세 근거와 분석 | 핵심 이벤트·수치·시간·분석 및 이전 사건 이력. 일반 설명을 사건의 확정 원인으로 대체하지 않음 |
| 4 | 보충 절차·참고 자료 | 공통 대응 절차는 펼침 영역. 권고는 수행 조건·점검 방법을 보존하며 자동 실행 아님 |
| 5 | 검토·조치 기록 | 사건 처리/검토 상태, 의견, 실제 조치와 정정 이력 |

최신 공개 결과 선정은 [02 조회 보완 계약](../backend/02_백엔드_API_작업명세서.md#gui-개편용-사건-분석-요약)을 따른다. 최신 작업이 미발행이면 기존 공개 분석의 시각·대상을 유지하고 새 진행 상태를 별도로 보여준다. 이전 분석을 새 작업의 결과처럼 표시하지 않는다.

`이전 분석`은 펼칠 때 페이지 단위로 조회한다. `/analyses/:id` 직접 링크는 해당 분석본을 그대로 연다. 보고서에서 참조한 과거 분석을 최신 분석으로 치환하지 않는다. 결과 없음·조회 실패·사건 연결 미확인은 별도 안내하고 미발행 본문을 추정하지 않는다.

`state`는 사건 처리, `alarm_status`는 알림, `review_status`는 검토, job 상태는 실행, `result_ref`는 공개 여부, 결과 품질은 판단 범위다. 알림 해제·결과 작성 완료를 고장 확정·복구 완료·사람의 종결로 바꾸지 않는다.

운영자가 참고할 Runbook 지침·출처 링크는 남긴다. 선택 과정·revision/hash·LLM 평가 원본·원본 근거 모달은 개발용이다. 과거 결과도 사람이 읽는 필드로 제공하며 JSON을 대체 화면으로 내놓지 않는다.

### 검토와 실제 조치 기록

새 RCA 의견·검토·조치는 사건 화면의 `subject_type=incident`로 남긴다. 분석본 직접 링크에서는 해당 RCA 선택을 보존한 채 원래 사건의 기록 위치로 연결한다. 분석별 과거 `subject_type=job` 기록은 `분석별 이전 기록 보기`에서 읽기 전용으로 유지하고 사건 기록으로 이관·병합하지 않는다. 보고서 기록은 계속 `subject_type=job`이다.

사건 처리 상태와 검토 상태는 별도 조작으로 바꾼다. 기록 저장 후 검토 완료나 종결로 자동 변경하지 않으며 기록 영역에 현재 검토 상태와 상태 변경 링크를 표시한다. 사건·분석·보고서의 조치 대상은 각각 저장된 범위를 사용하고 현재 전역 선택으로 대체하지 않는다.

신규 입력은 의견/검토/수행한 조치, 내용, 수행 시각·수행자·조치 요약·대상이다. 구조화 target을 기본값으로 보여주고 내부 ID는 화면이 전달한다. 대상이 불완전하거나 보고서처럼 범위가 여러 개이면 기존 관측 대상 조회와 명명된 선택 필드로 보완한다. 신원을 확인할 수 없으면 조치 저장만 막고 이유를 설명하며 의견·검토는 허용한다. UUID 추정·자유 JSON 입력은 금지한다.

근거 ID 직접 입력을 없앤다. 선택할 근거가 있으면 이름·시간으로 선택하고 기존 ID를 전달한다. 미선택은 기존 빈 참조 의미를 유지하고 전체 근거를 자동 첨부하지 않는다. 정정은 원본 연결과 기존 참조를 보존한다. 대상·시각·근거 서버 검증 및 수행자 미인증 의미를 유지한다. 기록 작성은 실제 장비 조치 실행이 아니다.

### S08 운영 보고서 목록

요청 한 건을 한 행/카드로 표시한다. 제목, 대상, 분석 기간, 접수 시각, 직접/자동 생성, 작성 상태, 자료 상태를 구분하고 최신 요청 순으로 정렬한다. 새 요청이 진행 중이라고 과거 보고서를 최신 요청 결과처럼 대체하지 않는다.

제목은 발행 여부와 무관하게 `/reports/:id`로 연결한다. 미발행은 같은 상세의 작성 현황이다. 상단은 `보고서 만들기`, 하위 탐색은 `보고서 목록 / 자동 보고서 설정`, 이용 안내는 보조 링크다.

운영 콘솔은 분석일 검색을 앞에 두고 상태·주제·요청 접수일은 보조 조건으로 제공한다. `report_preview`의 저장된 주요 변화와 관측·해석 한계를 읽고 상세를 선택한다. `method`와 `narrative_status`를 함께 확인해 AI 해석·AI가 고른 변화·계산 요약을 구분하며 요약 부재·발췌 여부를 표시한다. 목록에서 새 요약이나 권고를 생성하지 않는다. 전체 내용은 저장된 본문에서 읽는다.

### S09 보고서 생성과 자동 설정

신규 기본 보고서는 현재 집계 계약을 사용한다. 클러스터/Namespace, 일간·주간, 기준 날짜, 직접/자동 생성, 자동 시각·요일을 입력한다. 제출 전 실제 분석 시작·종료와 KST, 직전 동일 기간 비교를 확인시킨다. 내부 주제 코드·group_by·실행 프로필은 입력받지 않는다.

직접 요청은 접수 후 `/reports/:id`, 자동 설정은 `/schedules/:id`로 이동한다. 화면 닫기·모드 전환은 요청 취소가 아니다. 전송 실패에서 중복 생성하지 않는 멱등 처리를 유지한다.

자동 설정은 대상·주기·시각·다음 실행·활성 여부·최근 회차 상태를 표시한다. 회차 접수와 작업 실행을 구분하며 보고서는 `/reports/:id`로 연다. job이 없는 회차도 예정 시각·전달 실패 이유를 표시한다. 일정 정지는 이미 접수된 작업을 취소하지 않는다.

신규 집계 일정은 일간·주간만 허용한다. 기존 O계열 월간/다른 시간대 일정은 그대로 조회·편집하고 report_spec을 바꾸지 않는다. 구 생성 링크(`legacy`/`kind`)는 개발용 호환 폼을 보존하고 신규에는 명시적 개발용 전환 안내를 제공한다. 구 조건을 신규 집계 조건으로 조용히 치환하지 않는다.

### S10 운영 보고서 상세

읽기 순서는 저장된 핵심 해석 → Namespace 관측·기간 비교 → 기간 내 사건 → 확인할 사항·집계 기준이다. 저장 요약이 없으면 유효한 표·관측부터 보여주며 프론트에서 AI 해석이나 권고를 새로 작성하지 않는다.

- GPU 활동률, 메모리 비율·GPU당 용량, 작업 보조 관측, 완료 Job 표본 등 결과에 있는 내용을 유지한다. 구 결과의 미기록 필드는 만들어 채우지 않는다.
- 다중 모델 평균을 임의로 합치거나 공백을 0으로 연결하지 않는다. 관측 활동은 실소비·독점 할당·회수 가능 GPU가 아니다.
- 대기 Pod 최대값은 개수이며 대기 시간이 아니다. Job 경과시간은 대기·준비 포함이며 순수 실행시간이 아니다.
- 저장된 Namespace 운영 제안의 요약·조건·근거를 보존한다. 선별 숫자를 운영 정책이나 자동 조치로 승격하지 않는다. 전체/전달 후보 수 같은 실행 진단은 개발용으로 옮기되 조언의 전제는 신규에 남긴다.
- 사건 알림 상태는 작성 당시 기준이다. 공개 분석 링크는 저장된 분석본으로, 없으면 사건 신규 상세로 연결한다. 실시간 값으로 저장 보고서를 바꾸지 않는다.
- `근거 자세히`는 의미 있는 표·시간·출처·자료 한계다. 원본 evidence 응답·쿼리 모달로 연결하지 않는다.
- 신규의 `현재 화면 HTML 저장`은 렌더링된 결과·범위·기간·제한을 저장한다. 화면에서 선택된 그래프/분석 범위임을 파일에 표시하며 버튼·폼·링크를 제거하고 CSP를 포함한다. 출력의 진단 노출과 표시 결과 일치를 검수한다. CSV 원시 수치 내보내기는 개발용에 유지한다. 다운로드 API는 제거하지 않는다.
- 취소·기술 재시도는 기존 `can_cancel/can_retry` 허용 시 신규 작성 현황의 보조 동작으로 제공한다. 새 조건 요청과 같은 작업 재시도를 구분한다. 영구 삭제는 더보기 안에서 기존 확인·사유·버전·참조 보호를 유지한다.

### 개발용 유지 범위

S02 자산, S03 작업 연결, S04 관측 품질, S11 작업 디버깅, S12 지식, S13 모델, S14 라우팅, S15 데이터 설정 및 Backend 연결을 유지한다. 워크플로우 모달, 시도/근거/원본, revision 비교, API 기록, 보고서 명령·CSV 기능을 축소하지 않는다.

공유 결과 본문·표·그래프를 재사용하고 개발용 진단을 별도 구성으로 둔다. 상세 계약은 [07 RCA 평가 분리 표시](07_프론트엔드_개발명세서.md#rca-평가-분리-표시)를 따른다. 기존 화면 ID는 검수·문서 참조를 위해 보존한다.

## 경로와 이동 규칙

기존 URL을 유지하고 모드별 표현을 선택한다. 전체 경로를 `/dev` 하위로 재배치하지 않는다. 모드 저장값 이행은 07을 따른다.

| 진입/동작 | 신규 화면 처리 |
|---|---|
| `/`, `/dashboard` | 운영 현황 |
| `/cases` | 사건 중심 장애 분석 목록 |
| `/incidents/:id` | 해당 사건과 공개 분석 |
| `/analyses/:id` | 해당 분석본 전용 읽기. 연결 사건 이동 제공 |
| `/analyses/new` | 기존대로 `/cases`; 수동 생성 없음 |
| `/reports`, `/reports/new`, `/reports/:id` | 목록·생성·작성 현황/공개 결과 |
| `/schedules`, `/schedules/:id` | 운영 보고서 하위 자동 설정 |
| `/operator-guide` | 신규 이용 안내. 개발용 용어·링크는 역할별 구분 |
| `/jobs/:id` 직접 진입 | 종류·연결만 확인해 RCA는 `/analyses/:id`, report는 `/reports/:id`로 replace. 조회 실패 시 재조회 안내; 디버깅 자동 렌더 금지 |
| `/jobs`, `/fleet/*`, `/knowledge`, `/settings/*` | 신규 안내와 `개발용으로 전환하여 열기`. 자동 모드 변경 금지 |
| 개발용 → 신규 전환 | 공통 상세는 같은 ID. 작업 상세는 위 변환. 대응 신규 화면 없는 메뉴는 운영 현황 |
| 구 `/cases?tab=incidents` | `/cases`로 정규화, 지원되는 기간·사건 상태 필터 보존 |
| 구 `/cases?tab=analyses` 또는 `reports` | 신규 사건 목록으로 이동하며 이전 조사 필터 미적용 안내. 실행 상태를 사건 상태로 전달하지 않음. 개발용에서는 구 의미 보존 |
| 구 `/reports?tab=final` | 기존 완료 작업 필터 의미 유지. 공개 여부는 별도 확인 |

신규의 내부 링크는 신규의 상세/목록/이용 안내에서 끝나야 한다. 개발용 진입은 명시적 전환으로 통일한다. 클러스터 0건은 신규의 환경 준비 안내와 모드 전환, 개발용의 등록 화면 접근으로 처리한다. API 연결 실패와 0건을 구분한다.

목록 필터·추가 로드 행·선택 행·스크롤을 상세 방문 후 복원한다. 보고서 → 사건/과거 분석 → 보고서도 출발 지점을 유지한다. 직접 진입/새로고침으로 출발 정보가 없으면 종류별 기본 목록으로 돌아간다. 외부 URL을 return path로 받지 않는다. 저장 상세 범위는 전역 범위로 덮어쓰지 않는다.

작성 중 모드 전환은 입력을 보존한다. 보존 불가능한 화면 전환에만 이탈 확인을 제공하고 선택 전 입력을 버리지 않는다. 브라우저 뒤로 가기·새로고침·저장소 접근 실패도 검사한다.

## 상태와 오류 표현

| 상태 | 신규 표현과 동작 |
|---|---|
| 초기 조회 | 불러오는 중. 다른 대상의 캐시 결과가 섞이지 않음 |
| 성공·0건 | 조건에 맞는 사건/보고서 없음, 필터 해제 또는 보고서 생성 |
| 네트워크/서버 오류 | 조회 실패와 재조회. 빈 목록으로 대체하지 않음 |
| queued / retry_wait | 접수됨·처리 대기 / 일시 오류로 재시도 대기. 알려진 사유만 설명 |
| running | 분석 중/작성 중. 저장된 시작 시각만 표시; 가짜 진행률·예정시간 없음 |
| succeeded, result_ref 없음 | 처리 완료·공개 결과 없음. 최종 결과 버튼 없음 |
| 공개 + partial/blocked | 결과와 자료 부족·판단 불가 범위를 함께 표시 |
| failed/cancelled/expired | 종료 상태·필요한 사유, 허용된 보고서 후속 명령 |
| 설명 실패·생략 | 유효 수치·관측 유지, 설명 미제공 안내 |
| 구 형식/필드 부재 | 저장 내용 읽기 유지, 미기록을 0·정상·신규 판단으로 보충하지 않음 |
| 삭제 보고서 직접 링크 | 삭제·최소 기록·파일 정리 상태. 빈 결과나 복구 성공으로 표시하지 않음 |

## 화면 검수 기준

신규·운영 콘솔에서 사건 확인·결론 이해·다음 행동·보고서 생성·일정 관리·기록 작성·다운로드가 개발용 진입 없이 끝나야 한다. 원본을 제거하면서 판단 한계·근거·기존 결과를 잃지 않아야 한다. 1280px 이상과 390px/320px, 키보드·포커스·표 대체 설명, 긴 이름·결과를 검사한다. 시나리오와 합격 조건은 [05](../05_테스트_검수_기준서.md#여섯-탭-gui-검수)에 한 번만 정의한다.
